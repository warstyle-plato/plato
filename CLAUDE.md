# PLATO / DevelopAid — рабочий контекст

Этот файл читается в начале каждой сессии. Он содержит только постоянно нужные правила.
История поломок и подробные кейсы НЕ должны добавляться сюда.

- Полный снимок старого файла: `docs/CLAUDE_HISTORY_2026-09-20.md`.
- Короткий индекс правил с исходными строками: `docs/CLAUDE_RULE_INDEX.md`.
- Перед изменением конкретного узла сначала ищи в индексе имя файла, функции, маршрута или предмета; в архиве читай только совпавший фрагмент.
- Новые подробные разборы и уроки добавляй в архив/профильный документ, а в этот файл — только короткое устойчивое правило, без истории инцидента, дат и длинных примеров.
- Цель: корневой `CLAUDE.md` остаётся коротким. Не превращать его снова в журнал разработки.

## Устройство

- `main_legacy.py` — основной движок: расчёт, страница (`PAGE`), Telegram-бот, Excel, PDF, агент Платон Сергеевич.
- `main.py` — обёртка: грузит движок как `developaid_core`, патчит поведение бота, хранит контекст Платона; `core = _load_core()`, `app = core.app`.
- Бот и движок — один процесс, не разные сервисы.
- Прод работает двумя воркерами (`--workers 2`); память у них раздельная. Состояние, которое должно пережить переход между сообщениями, хранить на диске (`_STATE_DIR`, указатель `chat:{id}`).
- Задачи и вопросы живут в `docs/questions_backlog.md`; не дублировать этот список здесь.

## Базовые инварианты

- Один вопрос — один владелец ответа. Если одно и то же число, правило, легенда, версия или состояние собирается в нескольких местах, свести к одному источнику и заставить остальные поверхности читать его.
- Не подменять отсутствие данных решением пользователя: отсутствующий ключ не равен `false`, пустое поле не равно нулю, отсутствие записи не равно «снято».
- Сохранённое состояние браузера накладывается на текущие умолчания, а не заменяет их целиком.
- Любое автоматически рассчитанное поле должно хранить происхождение значения. Значение нормы/импорта не должно после сохранения выглядеть как ручное.
- Производное число нельзя замораживать после изменения его входов. Если ТЭП/площадь/класс/норма изменились, зависимое значение пересчитывается, если пользователь явно не зафиксировал его вручную.
- Не угадывать схему по имени поля, позиции, порядку или соседнему объекту. Для критичных соответствий использовать явные карты/идентификаторы.
- Если правило объявлено одним предикатом/функцией, все читатели этого решения должны пользоваться им; проверять читателей, а не только место объявления.
- Любой отказ или «нет данных» обязан называть реальную причину и источник наблюдения. Не обвинять внешний источник, если пропущено наше поле или наш маршрут.
- Ошибка только в логе считается невидимой: важную причину доносить пользователю/оператору с местом возникновения.
- Тяжёлые PDF/Excel/долгие расчёты не выполнять синхронно внутри запроса, от которого зависит окно/бот.
- Telegram session token не идентифицирует проект; чат идентифицировать по `chat_id`.

## Экономика, ТЭП и Excel

- Авторитетный расчёт выполнять один раз и раздавать его результат всем поверхностям. Не считать отдельно для PDF, Excel, Telegram и страницы без явной причины.
- Методика должна совпадать в движке и книге. Любая правка формулы требует проверки обеих реализаций.
- Формулы шаблона ПЛАТО не переписывать, кроме явно разрешённого списка `_PLATO_OVERRIDE_TEMPLATE_FORMULA`; колонку G не трогать.
- Если формула/ячейка шаблона не распознана, это `missing/error`, а не молчаливый успех.
- `audit_plato_workbook` сравнивает рассчитанную книгу с движком. Формулы openpyxl не вычисляет: для содержательной сверки нужна книга, пересчитанная Excel и сохранённая.
- LibreOffice в песочнице не считать надёжной заменой Excel.
- Для нормативов и городских смягчений различать: обязательная формула, справочная возможность и решение органа власти. Не превращать справочное право/дискрецию в автоматический множитель.

## КРТ, торги и внешние данные

- «Лот существует» и «идут торги» — разные состояния. Живой лот определяется сроком/статусом, а не наличием поля или старой связки.
- Просроченный лот не должен поддерживать состояние «идёт аукцион»; причина должна сообщать, что приём заявок закончился.
- Связки и снимки, переживающие релизы, обязаны иметь проверку свежести/актуальности.
- Первый снимок сторожа не генерирует новости; последующие изменения должны быть наблюдаемы счётчиками и диагностикой.
- Ноль, полученный из маршрута или поля, которое не содержит нужную величину, не считать ответом источника.
- Для площадки, решения, лота и объекта не смешивать доказательства соседних сущностей. Адрес, кадастр, паспортные числа и идентификаторы имеют разную силу; подробные правила искать в историческом индексе.

## UI и проверки

- Присланный владельцем образец (PDF, презентация) задаёт СОСТАВ поверхности блок за блоком; ТЗ по нему — только рамка. Сверять с образцом механически до того, как объявлять поверхность готовой.
- Проверять то, что видит пользователь. Для HTML/JS порядок элементов, подписи, видимость, прокрутку и итоговые значения мерить на отрисованной странице/в браузере, а не по позиции литералов в исходнике.
- Тесты страницы должны выполнять настоящий код из `PAGE`, а не копию логики.
- Проверка должна падать на подделке/контрпримере; зелёный тест, который проходит на сломанном варианте, ничего не доказывает.
- Маркеры merge-конфликтов не должны переживать слияние.
- CI rollup может показывать failure для отменённого прогона. Для диагноза смотреть состояния долей/jobs: `cancelled` не равно настоящему `failure`.
- Не отправлять новый push, если правка может дождаться текущего длительного CI: новый push снимает предыдущий прогон.

## Команды проверки

- Полный набор: `bash scripts/run_tests.sh`.
- Доля: `TEST_SHARDS=4 TEST_SHARD=2 bash scripts/run_tests.sh`.
- План долей: `python3 scripts/test_shards.py --shards 4 --plan`.
- Число тестов и длительность быстро меняются; не хранить здесь устаревающие счётчики. Смотреть текущий CI.
- При приёмке шардов проверять, что сумма collected/passed/skipped по долям соответствует целому набору.

## Стенд и маршрутизация

- Render — бот и мини-приложение; Яндекс — ядро с доступом к НСПД.
- Переменные: `MO_CALC_API_URL`, `TELEGRAM_WEBAPP_URL`, `PLATO_AI_URL`, `PLATO_AI_PROXY_SECRET`.
- На ядре `MO_CALC_API_URL` и `TELEGRAM_WEBAPP_URL` должны быть пустыми, иначе запрос может уйти по кругу.
- На ядре `PLATO_AI_URL` и `PLATO_AI_PROXY_SECRET` нужны для маршрута модели на Render, где хранится `OPENAI_API_KEY`.
- Основной интерфейс — корень; прежний вид — `/classic`; стендовый адрес `/ia` остаётся.
- В Telegram IA-слой отключает себя по `telegram_session` / `cad` в hash.
- IA preview собирается workflow «IA preview» из веток `claude/developaid-ia-*`, поднимается `deploy-ia-preview.sh` на 18081 и не должен трогать рабочий 8080.
- Маршрут Платона виден в `/agent/status` полем `route` (`render_proxy` / `local_openai`) и в журнале.

## Как сохранять новое знание

Если ошибка дала устойчивое правило:
1. Исправь код и добавь проверку.
2. Полный разбор инцидента сохрани в профильном `docs/*.md` или в историческом архиве.
3. В этот файл добавляй максимум одну короткую строку только если правило действительно нужно почти каждой будущей сессии.
4. Не вставляй сюда логи, даты прогонов, длинные цитаты, конкретные числа одного кейса и хронику PR.
