# DevelopAid — статистика себестоимости

## Цель

Отдельный статистический контур для сайта и Telegram-бота: региональные ориентиры стоимости строительства по классам жилья с прозрачным составом источников и уровнем достоверности.

## Источники

1. **ЕИСЖС / наш.дом.рф** — первичная объектная выборка. Используем только официально доступный API/экспорт. Ключевые поля: регион, город, класс объекта, планируемая стоимость строительства, площади, этажность, конструктив, дата проектной декларации. Не парсим PDF, если то же поле доступно структурированно.
2. **Росстат** — индексы цен производителей на строительную продукцию и индексы по группам ОКС. Используются для приведения наблюдений разных дат к общей ценовой дате; не используются как самостоятельная себестоимость проекта.
3. **СИС / ЕРЗ** — независимый региональный reference. Не смешивается арифметически с ЕИСЖС, поскольку состав затрат и знаменатель могут отличаться. Предпочтение: лицензированная структурированная выгрузка; затем официальный файл; HTML-таблица — только если условия использования это допускают.
4. **DevelopAid plan/fact** — будущий внутренний обезличенный слой фактической стоимости из РСС/план-факта. До появления достаточной выборки не участвует в публичном benchmark.

## Единицы

Всегда храним отдельно:

- RUB / m² GBA;
- RUB / m² площади квартир;
- RUB / m² продаваемой площади.

Пересчёт между знаменателями без подтверждённых площадей запрещён.

## Алгоритм выборки

Базовые фильтры: регион + класс. Дополнительные: город, этажность, конструктив, подземный паркинг.

Если выборка меньше 5 наблюдений, фильтры ослабляются строго в порядке:

1. паркинг;
2. конструктив;
3. этажность;
4. город.

Класс не ослабляется автоматически. Регион не ослабляется автоматически.

Достоверность:

- N >= 20 — high;
- N 10–19 — medium;
- N 5–9 — limited;
- N < 5 — insufficient.

При N >= 8 применяется IQR-фильтр выбросов. Каждое исходное наблюдение должно сохранять source, external_id, reference_date и source_url, когда URL доступен.

## DevelopAid recommended

Версия 1.0: медиана очищенной объектной выборки ЕИСЖС. Внешний benchmark СИС/ЕРЗ показывается рядом, но не усредняется с ней. Это сделано намеренно: среднее двух методологически разных величин создаёт ложную точность.

Следующая версия может вводить корректировки за дату, этажность, конструктив и паркинг только после backtest на фактических проектах.

## Что уже реализовано в ветке

- `developaid_statistics.py` — каноническая схема наблюдений, нормализация класса, выборка, ослабление фильтров, P25/Median/P75, confidence.
- `statistics_sources.py` — source registry, адаптер импорта ЕИСЖС JSON и внешних benchmark CSV, конфигурация API через `EISZH_API_BASE` / `EISZH_API_TOKEN`.
- `statistics_preview.py` — отдельный FastAPI preview с `/statistics`, `/health`, `/api/statistics/construction-cost`.
- `tests/test_statistics_engine.py` — базовые unit tests статистической логики.

## Что нельзя делать

- Не показывать придуманную цифру при пустой выборке.
- Не смешивать стоимость / GBA и стоимость / площадь квартир.
- Не называть показатель СИС/ЕРЗ «CAPEX DevelopAid» без раскрытия состава затрат.
- Не скрейпить закрытые/защищённые endpoints ЕИСЖС в обход доступа.
- Не публиковать внутренние проектные данные DevelopAid без обезличивания и минимального размера группы.

## Рекомендации по production

1. Получить официальный доступ к ЕИСЖС API либо официальный структурированный экспорт и закрепить разрешённый способ повторного использования производной статистики.
2. Хранить raw snapshot отдельно от normalized observations. Никогда не перезаписывать историю ПД.
3. Обновлять ЕИСЖС ежедневно инкрементально, Росстат — после месячной публикации, СИС/ЕРЗ — по новой публикации.
4. Для публичной страницы показывать дату последней синхронизации каждого источника и N выборки.
5. Для бота использовать только нашу агрегированную API, не ходить во внешние источники в пользовательском запросе.
6. При N < 5 показывать внешний reference и предупреждение, но не формировать DevelopAid recommended.
7. После накопления факта провести backtest: заявленная стоимость ЕИСЖС против EAC/факта реальных проектов. Только после этого вводить коэффициенты класса/этажности/паркинга.
