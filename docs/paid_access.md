# Платный доступ к расчёту

Решения владельца (21.10.2026):

- без входа (через Telegram) расчёт экономики не запускается ни на одной поверхности;
- после входа — бесплатные участки, `DEVELOPAID_FREE_PLOTS` (по умолчанию 1);
- дальше — доступ к участку на `DEVELOPAID_PLOT_DAYS` дней (30) за
  `DEVELOPAID_PLOT_PRICE_RUB` (10 000 ₽): любое число пересчётов, PDF и Excel;
  или подписка `DEVELOPAID_SUBSCRIPTION_PRICE_RUB` (100 000 ₽) на
  `DEVELOPAID_SUBSCRIPTION_DAYS` дней (30) без ограничения участков;
- **участок — набор кадастровых номеров**. Оплаченный набор открывает любой расчёт
  из этих же номеров в любом порядке (и любую их часть). Новый номер, даже
  соседний, — уже другой участок;
- **проект без кадастрового номера** (ТЭП загружен файлом) — участок сам по себе:
  страница даёт ему `inputs._project_uid` при загрузке, бот опознаёт его по имени
  проекта;
- ни номера, ни проекта — не участок: расчёт открыт только подписке и
  администраторам, бесплатный участок на это не тратится;
- администраторы (`DEVELOPAID_ADMIN_IDS`, ключ `DEVELOPAID_ADMIN_KEY`) считают без
  ограничений.

## Выключатель замка

Замок включается **только вместе с работающей оплатой** (решение владельца 21.10.2026):
`DEVELOPAID_PAYWALL=1`. По умолчанию выключен — расчёт ведёт себя как прежде: без входа
закрыт, после входа считается любой участок, бесплатный не тратится, учёт не пишется.

Порядок включения: ключи ЮKassa в окружение → тестовый платёж прошёл и открыл участок →
`DEVELOPAID_PAYWALL=1` на Render и на ядре.

Ключ кабинета рынка (`MARKET_CABINET_KEY`, кука `market_cabinet` / заголовок
`X-Market-Key`) — команда владельца: при включённом замке полный доступ без счёта
участков, как ключ администратора. Проверку делает `market_search.cabinet.authorised`;
запрос до решения доносит слой `_AccessScopeMiddleware`.

## Устройство

`engine/access_rights.py`:

- `access_plot(inputs, cadastral)` — что считать участком. Номера берутся
  `_project_cadastral_numbers`, тем же, что читают PDF, тизер и книга;
- `calc_access_for_chat(chat, what, ...)` — **единственное** решение «можно ли считать
  этот участок». Отказ — HTTP 402 со словами, что сделать;
- `require_calc_access(session, key, what, ...)` — вход + право; для сырых JSON-запросов
  `require_payload_access(payload, what)`;
- `access_grant(...)` — выдача участка или подписки; повтор того же `payment_id` не
  продлевает второй раз;
- `access_status(chat)` — права для кабинета.

Права лежат на ядре (`<DEVELOPAID_PROJECTS_DIR>/../access/{chat}.json`), рядом с
профилями: диск Render живёт до выкатки. Запись — под `fcntl.flock` (воркеров два),
каждое событие — строка в `access/journal.jsonl`. Render спрашивает ядро
`POST /internal/access/use`, подпись — токеном бота; положительный ответ кэшируется на
минуту, отказ не кэшируется.

Без `TELEGRAM_BOT_TOKEN` механизм выключен, как и вход: проверять подпись нечем.

## Читатели

Маршруты, которые зовут решение: `/calculate`, `/calculate-phased`,
`/analysis/sensitivity`, `/report/pdf`, `/report/teaser`, `/report/workbook`,
`/agent/chat`, `/ia/goal-seek`, `/api/v2/calculate`, `/telegram/result`; в боте —
Excel-модель (`_send_model_archive`) и Платон (`_run_agent`), через
`_bot_calc_allowed`. Проверка по читателям — `tests/test_paid_access_rights.py`.

Каталог КРТ: `/auctions/krt/ranking` (весь рейтинг — без участка: при включённом замке
по подписке) и `/auctions/krt/{slug}/investment-score` (участок — номера площадки) зовут
`catalog_economics_access`; страница торгов шлёт сессию заголовком `X-Developaid-Session`.
Демо DevelopAid 2.0 (`/api/v2/projects/{slug}`) открыты (решение владельца).

Не трогается: участок, ТЭП и ограничения (`/mo/calculate`, `/cadastral/*`, ВРИ/ТЭП в
боте) и разбор документа — экономику они не считают.

## Открытые вопросы владельцу

- тексты оферты (лицензионного договора) и политики возврата — места под них, оплата
  включается только с ними.

## Оплата (ЮKassa)

`engine/payments.py`. Оплата включается, только когда выполнено всё сразу
(`payments_missing()` называет, чего нет):

- заданы `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` (вносит владелец; в коде и журнале их нет);
- вписаны `docs/legal/offer.md` и `docs/legal/refund.md` (пока в файле строка `ЗАГОТОВКА:` —
  выключено);
- для ставки `DEVELOPAID_VAT_PCT` есть код чека.

Маршруты: `POST /payments/create` (вход обязателен, нужна почта для чека),
`GET /payments/return` (страница возврата спрашивает статус), `POST /payments/status`,
`POST /payments/yookassa/webhook`, `GET /payments/terms`, `GET /offer`, `GET /refund`.

- Права выдаёт только платёж, **перечитанный из API** (`GET /v3/payments/{id}`) со статусом
  `succeeded` и суммой, равной цене заказа. Тело уведомления и возврат браузера прав не дают.
- Уведомление принимается с адресов ЮKassa (за прокси — последний адрес `X-Forwarded-For`);
  временная ошибка — 503, ЮKassa повторяет сутки. Повтор не продлевает доступ (`payment_id`).
- Всё для выдачи лежит в `metadata` платежа; Render передаёт выдачу на ядро подписанным
  `POST /internal/access/grant`.
- Чек 54-ФЗ: `vat_code` 7 («НДС по ставке 5%»: цена включает налог, расчёт полный),
  `payment_mode=full_payment`, `payment_subject` — `DEVELOPAID_RECEIPT_SUBJECT`
  (по умолчанию `intellectual_activity`, уточнить у бухгалтера), выключатель
  `DEVELOPAID_RECEIPTS`.
- Адрес возврата — `DEVELOPAID_PUBLIC_URL` + `/payments/return`.
- В кабинете ЮKassa: адрес уведомлений `https://<сайт>/payments/yookassa/webhook`, события
  `payment.succeeded` и `payment.canceled`.
- Подписка продлевается повторной оплатой; автоплатёж требует согласования с ЮKassa и
  отдельного текста согласия — не сделан.

Реквизиты программы — `docs/legal/product.json` (`product_info()`,
`product_registration_line()`).

## Кабинет, тарифы, администрирование

- Страница: кнопка «Тарифы» в шапке открывает «Личный кабинет» на разделе «Тарифы и доступ»
  (`tariffsHtml`, `renderTariffsBox`): цены с «в том числе НДС», остаток бесплатного,
  открытые участки со сроками, подписка; кнопки оплаты — только когда сервер включил оплату.
  Панель закрытой экономики (402) ведёт туда же. В подвале — договор, возврат и строка о
  регистрации программы (`__DEVELOPAID_PRODUCT_REGISTRATION__` ← `product_registration_line`).
- `POST /access/me` — условия и мои права; на Render права спрашиваются у ядра
  (`/internal/access/me`).
- Администраторам (`DEVELOPAID_ADMIN_IDS` или ключ): `POST /access/admin/overview` (люди,
  права, оплаты, журнал) и `POST /access/admin/grant` (участок или подписка на N дней).
  На странице — блок «Администрирование доступа» в кабинете.
- Бот: `/tariffs` (`/тарифы`) — те же условия и права; `/grant ID дней номера…` или
  `/grant ID дней подписка` — ручная выдача администратором.

## Модерация ЮKassa: публичные страницы и демо-доступ

`engine/review_demo.py` (решение владельца 22.10.2026).

- Без входа: `/tariffs` (цены «в том числе НДС», что входит, как оплатить), `/contacts`
  (реквизиты продавца), `/offer`, `/refund` (пока заготовки — помечены «Заготовка»). Ссылки
  в подвале всех страниц. Реквизиты продавца — блок `seller` в `docs/legal/product.json`.
- Демо-ссылка — кому угодно (клиенту, партнёру, проверяющему ЮKassa), в комментарии — для кого: администратор в кабинете → «Администрирование доступа» → «Демо-доступ по ссылке» →
  «Создать демо-ссылку» (`/access/admin/demo/create`, срок `DEVELOPAID_DEMO_DAYS`, 14 дней).
  `/demo/<код>` показывает, как входит клиент, и открывает кабинет без Telegram на
  «Тарифах и доступе». Демо-пользователь — отдельный `chat_id` (диапазон от
  `_DEMO_CHAT_BASE`): права нового клиента, своих проектов нет, чужих не видит, админка
  закрыта. Отзыв (`/access/admin/demo/revoke`) гасит и выданную сессию
  (`demo_session_alive` в `_telegram_verify_session`).
- Оплата в демо: тестовый магазин ЮKassa (`YOOKASSA_TEST_SHOP_ID`, `YOOKASSA_TEST_SECRET_KEY`),
  а без него — пояснение, где откроется форма. Тестовый платёж открывает доступ только
  демо-пользователю (`metadata.demo`).

## Два уровня доступа: «вошёл» и «команда владельца»

Решение владельца 22.10.2026. Вход через Telegram открывает расчёт, тарифы и свой личный
кабинет. Данные проектов владельца — монитор (`/monitor*`), сводка руководству (`/report` и
`/monitor/report*`), споры, записи, бюджеты, объединение проектов, рассылка — только команде:
`_require_team_access` / `team_access_allowed` (`engine/bot_users.py`).

Команда — ключ администратора (`DEVELOPAID_ADMIN_KEY`), ключ кабинета рынка
(`MARKET_CABINET_KEY`) или вход человека из `DEVELOPAID_ADMIN_IDS` и `DEVELOPAID_TEAM_IDS`
(по умолчанию пуст). Демо-доступ по ссылке — никогда. Подписчики сводки получают её в бот,
веб-доступ им не нужен. `/internal/report/*` подписаны ботом и остаются как были.
