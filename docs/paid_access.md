# Платный доступ к расчёту

Решения владельца (21.10.2026):

- без входа (через Telegram) расчёт экономики не запускается ни на одной поверхности;
- после входа — бесплатные участки, `DEVELOPAID_FREE_PLOTS` (по умолчанию 1);
- дальше — доступ к участку на `DEVELOPAID_PLOT_DAYS` дней (30) за
  `DEVELOPAID_PLOT_PRICE_RUB` (10 000 ₽): любое число пересчётов, PDF и Excel;
  или подписка `DEVELOPAID_SUBSCRIPTION_PRICE_RUB` (100 000 ₽) на
  `DEVELOPAID_SUBSCRIPTION_DAYS` дней (30) без ограничения участков;
- **участок — набор кадастровых номеров**. Оплаченный набор открывает любой расчёт
  из этих же номеров в любом порядке (и любую их часть). Новый номер, даже
  соседний, — уже другой участок;
- **проект без кадастрового номера** (ТЭП загружен файлом) — участок сам по себе:
  страница даёт ему `inputs._project_uid` при загрузке, бот опознаёт его по имени
  проекта;
- ни номера, ни проекта — не участок: расчёт открыт только подписке и
  администраторам, бесплатный участок на это не тратится;
- администраторы (`DEVELOPAID_ADMIN_IDS`, ключ `DEVELOPAID_ADMIN_KEY`) считают без
  ограничений.

## Устройство

`engine/access_rights.py`:

- `access_plot(inputs, cadastral)` — что считать участком. Номера берутся
  `_project_cadastral_numbers`, тем же, что читают PDF, тизер и книга;
- `calc_access_for_chat(chat, what, ...)` — **единственное** решение «можно ли считать
  этот участок». Отказ — HTTP 402 со словами, что сделать;
- `require_calc_access(session, key, what, ...)` — вход + право; для сырых JSON-запросов
  `require_payload_access(payload, what)`;
- `access_grant(...)` — выдача участка или подписки; повтор того же `payment_id` не
  продлевает второй раз;
- `access_status(chat)` — права для кабинета.

Права лежат на ядре (`<DEVELOPAID_PROJECTS_DIR>/../access/{chat}.json`), рядом с
профилями: диск Render живёт до выкатки. Запись — под `fcntl.flock` (воркеров два),
каждое событие — строка в `access/journal.jsonl`. Render спрашивает ядро
`POST /internal/access/use`, подпись — токеном бота; положительный ответ кэшируется на
минуту, отказ не кэшируется.

Без `TELEGRAM_BOT_TOKEN` механизм выключен, как и вход: проверять подпись нечем.

## Читатели

Маршруты, которые зовут решение: `/calculate`, `/calculate-phased`,
`/analysis/sensitivity`, `/report/pdf`, `/report/teaser`, `/report/workbook`,
`/agent/chat`, `/ia/goal-seek`, `/api/v2/calculate`, `/telegram/result`; в боте —
Excel-модель (`_send_model_archive`) и Платон (`_run_agent`), через
`_bot_calc_allowed`. Проверка по читателям — `tests/test_paid_access_rights.py`.

Не трогается: участок, ТЭП и ограничения (`/mo/calculate`, `/cadastral/*`, ВРИ/ТЭП в
боте) и разбор документа — экономику они не считают.

## Открытые вопросы владельцу

- демонстрационные проекты DevelopAid 2.0 (`/api/v2/projects/{slug}`) и экономика
  каталога КРТ на торгах считаются движком без участка пользователя — оставлены
  открытыми;
- тексты оферты (лицензионного договора) и политики возврата — места под них, оплата
  включается только с ними.
