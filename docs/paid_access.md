# Платный доступ к расчёту

Решения владельца (21.10.2026):

- без входа (через Telegram) расчёт экономики не запускается ни на одной поверхности;
- после входа — бесплатные участки, `DEVELOPAID_FREE_PLOTS` (по умолчанию 1);
- дальше — доступ к участку на `DEVELOPAID_PLOT_DAYS` дней (30) за
  `DEVELOPAID_PLOT_PRICE_RUB` (10 000 ₽): любое число пересчётов, PDF и Excel;
  или подписка `DEVELOPAID_SUBSCRIPTION_PRICE_RUB` (100 000 ₽) на
  `DEVELOPAID_SUBSCRIPTION_DAYS` дней (30) без ограничения участков;
- **участок — набор кадастровых номеров**. Оплаченный набор открывает любой расчёт
  из этих же номеров в любом порядке (и любую их часть). Новый номер, даже
  соседний, — уже другой участок;
- **проект без кадастрового номера** (ТЭП загружен файлом) — участок сам по себе:
  страница даёт ему `inputs._project_uid` при загрузке, бот опознаёт его по имени
  проекта;
- ни номера, ни проекта — не участок: расчёт открыт только подписке и
  администраторам, бесплатный участок на это не тратится;
- администраторы (`DEVELOPAID_ADMIN_IDS`, ключ `DEVELOPAID_ADMIN_KEY`) считают без
  ограничений;
- **несколько участков вперёд** (решение владельца 23.10.2026): пакет из N участков
  (1–`_PAYMENT_MAX_PLOTS`, 10) без скидки — N × цена участка. Текущий участок открывается
  сразу, остальные ложатся в **запас** (`record["reserve"]`, запись на участок с
  `happened_at` и `payment_id`); без текущего участка весь пакет — в запас. При первом
  расчёте участка без действующего права (новый или с истёкшим сроком) `access_use`
  после бесплатного и до отказа «нужна оплата» берёт участок из запаса: выдача
  `source: "reserve"` на `plot_days` от момента привязки, строка в журнале с
  `reserve_left`. Запас не тратится подпиской. Чек — одна позиция `quantity=N` по цене
  за единицу; повтор уведомления (`payment_id`) запас не удваивает.

## Выключатель замка

Замок включается **только вместе с работающей оплатой** (решение владельца 21.10.2026):
`DEVELOPAID_PAYWALL=1`. По умолчанию выключен — расчёт ведёт себя как прежде: без входа
закрыт, после входа считается любой участок, бесплатный не тратится, учёт не пишется.

Порядок включения: ключи ЮKassa в окружение → тестовый платёж прошёл и открыл участок →
`DEVELOPAID_PAYWALL=1` на Render и на ядре.

**Условие до включения** (аудит 23.10.2026, `docs/security_audit_2026-10-23.md`
п. 4.6): ключ участка без кадастровых номеров сейчас — `_project_uid` из
браузера, и один участок покрывает любые проекты; число номеров на участок не
ограничено. Пока это не исправлено, замок не включать.

Ключ кабинета рынка (`MARKET_CABINET_KEY`, кука `market_cabinet` / заголовок
`X-Market-Key`) — команда владельца: при включённом замке полный доступ без счёта
участков, как ключ администратора. Проверку делает `market_search.cabinet.authorised`;
запрос до решения доносит слой `_AccessScopeMiddleware`.

## Устройство

`engine/access_rights.py`:

- `access_plot(inputs, cadastral)` — что считать участком. Номера берутся
  `_project_cadastral_numbers`, тем же, что читают PDF, тизер и книга;
- `calc_access_for_chat(chat, what, ...)` — **единственное** решение «можно ли считать
  этот участок». Отказ — HTTP 402 со словами, что сделать;
- `require_calc_access(session, key, what, ...)` — вход + право; для сырых JSON-запросов
  `require_payload_access(payload, what)`;
- `access_grant(...)` — выдача участка, подписки или `reserve` участков в запас; повтор
  того же `payment_id` не продлевает второй раз;
- `access_status(chat)` — права для кабинета.

Права лежат на ядре (`<DEVELOPAID_PROJECTS_DIR>/../access/{chat}.json`), рядом с
профилями: диск Render живёт до выкатки. Запись — под `fcntl.flock` (воркеров два),
каждое событие — строка в `access/journal.jsonl`. Render спрашивает ядро
`POST /internal/access/use`, подпись — токеном бота; положительный ответ кэшируется на
минуту, отказ не кэшируется.

Без `TELEGRAM_BOT_TOKEN` механизм выключен, как и вход: проверять подпись нечем.

## Оплата (ЮKassa)

`engine/payments.py`. Оплата включается, только когда выполнено всё сразу
(`payments_missing()` называет, чего нет):

- заданы `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` (вносит владелец; в коде и журнале их нет);
- вписаны `docs/legal/offer.md` и `docs/legal/refund.md` (пока в файле строка `ЗАГОТОВКА:` —
  выключено);
- для ставки `DEVELOPAID_VAT_PCT` есть код чека.

Маршруты: `POST /payments/create` (вход обязателен, нужна почта для чека),
`GET /payments/return` (страница возврата спрашивает статус), `POST /payments/status`,
`POST /payments/yookassa/webhook`, `GET /payments/terms`, `GET /offer`, `GET /refund`.

- Права выдаёт только платёж, **перечитанный из API** (`GET /v3/payments/{id}`) со статусом
  `succeeded` и суммой, равной цене заказа. Тело уведомления и возврат браузера прав не дают.
- Уведомление принимается с адресов ЮKassa (за прокси — последний адрес `X-Forwarded-For`);
  временная ошибка — 503, ЮKassa повторяет сутки. Повтор не продлевает доступ (`payment_id`).
- Всё для выдачи лежит в `metadata` платежа; Render передаёт выдачу на ядро подписанным
  `POST /internal/access/grant`.
- Чек 54-ФЗ: `vat_code` 7 («НДС по ставке 5%»: цена включает налог, расчёт полный),
  `payment_mode=full_payment`, `payment_subject` — `DEVELOPAID_RECEIPT_SUBJECT`
  (по умолчанию `intellectual_activity`, уточнить у бухгалтера), выключатель
  `DEVELOPAID_RECEIPTS`.
- Адрес возврата — `DEVELOPAID_PUBLIC_URL` + `/payments/return`.
- В кабинете ЮKassa: адрес уведомлений `https://<сайт>/payments/yookassa/webhook`, события
  `payment.succeeded` и `payment.canceled`.
- Подписка продлевается повторной оплатой; автоплатёж требует согласования с ЮKassa и
  отдельного текста согласия — не сделан.

Реквизиты программы — `docs/legal/product.json` (`product_info()`,
`product_registration_line()`).

## Плашка доступа над расчётом

Решение владельца 25.10.2026: покупка предлагается там, где человек уже ввёл
участок и ждёт расчёт, — первой плашкой раздела «Результат» (`#calcLocked`,
`accessPlaqueHtml` в `engine/page_js_calc.py`), а не на входе и не в шапке.

- Ответ плашки — `POST /access/check`: то же `calc_access_for_chat`, но
  `preview=True` — без списания бесплатного и запаса, без 402 и без журнала.
  Страница право не вычисляет, а показывает ответ (`code`, `free_left`, участок,
  цены из `_access_offer`, общие с кабинетом).
- **Бесплатный участок с сайта тратится только кнопкой «Посчитать бесплатно»**:
  `/calculate` и `/calculate-phased` передают `use_free` → `free_consent`; без
  согласия ответ `free_offer` (402) и ничего не тратится. Опечатка в номере
  больше не съедает бесплатный участок. Бот, мини-приложение (`calc_access_for_chat`
  по умолчанию), каталог КРТ и DevelopAid 2.0 кнопки не имеют и дают согласие
  сами, как прежде. Остальные маршруты страницы (`require_calc_access`, по
  умолчанию без согласия) идут после расчёта, когда участок уже открыт.
- Платный участок: цена участка и подписки, поле почты для чека и кнопки
  оплаты прямо в плашке (`payForAccess(kind, 'calc')`); пакет из нескольких
  участков — в «Тарифах». Перед уходом на оплату вводные пишутся в браузер
  (`persistLocalSilently`), страница возврата после «оплата прошла» сама
  возвращает на расчёт, и он запускается.
- Пока плашка стоит, отчёт и вердикт прежнего участка спрятаны
  (`#report.calc-closed`), шапка слоя IA не пишет «Расчёт актуален».
- Открытый расчёт несёт `access` (`access_summary`): строка над отчётом
  `#calcAccessLine` — «открыт бесплатно до …, бесплатных осталось N», по
  подписке или из запаса.
- Проверка — `tests/test_paid_access_plaque.py` (на отрисованной странице).

## Кабинет, тарифы, администрирование

- **Весть человеку о выданном доступе** (решение владельца 26.10.2026): при любой выдаче —
  в кабинете, командой `/grant`, после оплаты — бот пишет человеку, что открыто и до какого
  числа (`access_grant_notify` в `access_grant`, текст — `access_grant_text`). Комментарий
  администратора — только для журнала, в сообщение не попадает. Не дошло (человек
  заблокировал бота, нет связи) — причина в ответе выдавшему (`notice`) и строка
  `notify_failed` в журнале; доступ при этом выдан. Повтор уведомления об оплате второго
  сообщения не шлёт. Демо-пользователям не пишется.

- Страница: кнопка «Тарифы» в шапке открывает «Личный кабинет» на разделе «Тарифы и доступ»
  (`tariffsHtml`, `renderTariffsBox`): цены с «в том числе НДС», остаток бесплатного,
  открытые участки со сроками, подписка; кнопки оплаты — только когда сервер включил оплату.
  Панель закрытой экономики (402) ведёт туда же. В подвале — договор, возврат и строка о
  регистрации программы (`__DEVELOPAID_PRODUCT_REGISTRATION__` ← `product_registration_line`).
- `POST /access/me` — условия и мои права; на Render права спрашиваются у ядра
  (`/internal/access/me`).
- Администраторам (`DEVELOPAID_ADMIN_IDS` или ключ): `POST /access/admin/overview` (люди,
  права, оплаты, журнал) и `POST /access/admin/grant` (участок или подписка на N дней).
  На странице — блок «Администрирование доступа» в кабинете.
- Бот: `/tariffs` (`/тарифы`) — те же условия и права, включая запас; `/grant ID дней номера…`,
  `/grant ID дней подписка` или `/grant ID запас N` — ручная выдача администратором.
- Кабинет: поле «Сколько участков» (1–10) рядом с «Оплатить текущий участок»; «В запасе
  участков: N»; привязанный из запаса участок помечен «(из запаса)». Админ-форма «Выдать
  доступ» — вариант «Запас: несколько участков вперёд».

  демо-пользователю (`metadata.demo`).

  `DEVELOPAID_TEAM_IDS`), демо-ссылка с разделами «monitor»/«report».
- Без токена бота закрыто так же (fail closed). Не задан `DEVELOPAID_ADMIN_KEY` — закрыто

- Отказ — 403 ««Раздел»: Раздел доступен только по ключу администратора.», без сведений о

- Ключ вводится кнопкой «Ключ администратора» на страницах `/monitor` и `/report`, хранится в

- Страницы-оболочки `/monitor` и `/report` открыты: в них нет чисел.
- `/internal/monitor/*` требует и подпись транспорта, и действующее разрешение владельца

  рассылка `/internal/report/*` сохраняет свой список получателей; управляет рассылкой только
  ключ. Этот список не даёт доступа к источникам Платона и другим закрытым операциям.
- Проверка: `tests/test_team_only_monitor.py` берёт маршруты из регистрации `app`.

### В Telegram — разрешение ключом на точные группу и проект

Владелец подтвердил 06.11.2026: «Разрешать ключом группу и проект». В закрытом кабинете
Монитора владелец с текущим ключом администратора явно выбирает проект и Telegram ID группы.
Это разрешает существующий приём ежедневных отчётов и фотографий, отчётов продаж и ответов
команды, а также уточняющие вопросы Платона по выбранному проекту. Вопросы могут содержать
факты из закрытой контрактации; их видят все участники этой группы. Новая рассылка полных
реестров, сводок и общий разговор с моделью в группе этим не включаются. Разрешение группы
не переносится на личные чаты её участников или другой проект.

- `POST /monitor/site-chats/authorize` и `/revoke` требуют текущий ключ администратора и
  точные `chat_id` и `project`. `GET /monitor/site-chats/access` с тем же ключом показывает
  состояние разрешений. Ключ передаётся заголовком `X-Developaid-Admin-Key` либо полем `key`
  тела POST; GET не получает его в адресе. Ответы этих маршрутов — `private, no-store`.
- Подписанные разрешения ядра хранятся отдельно от старого `site_chats.json`, без исходного
  ключа. Проверяются группа, проект, действие и поколение текущего ключа до закрытого чтения
  или записи. Отзыв и смена ключа закрывают прежнее разрешение; наблюдённое отсутствие ключа
  также требует повторной авторизации после его восстановления.
- `/site` не привязывает группу самостоятельно. Бот сообщает автору команды её ID и
  предлагает обратиться к закрытому кабинету. Ключ не вводят в группе или в вопросе Платону.
- Старые привязки не считаются согласием владельца и требуют явной повторной авторизации.
  История отчётов, фотографий, заданных вопросов и ответов сохраняется; разрешение того же
  проекта продолжает прежний журнал и не повторяет уже заданные вопросы.
- Вход Telegram, оплаченный доступ, ID администратора бота, поля `caller`/`is_admin`, подпись
  транспорта и `subscribed_projects` сами по себе права на закрытые источники не дают.
  Собственный загруженный документ и личный расчёт доступны как прежде, с отдельным
  серверным владельцем этого чата; это не допуск к источникам команды.
- `/status` не раскрывает проекты и счётчик групп по одной подписке на рассылку. Закрытые
  метаданные `/internal/monitor/site-chats` проверяет ядро по действующему разрешению точной
  группы и проекта; фильтрация происходит до чтения данных. Одинаковые названия групп и
  прежний проект той же группы не смешивают счётчики. Команда `/status` в группе по-прежнему
  не запускает рассылку данных в группу.
- Существующая еженедельная рассылка сводки использует отдельный список получателей на
  момент отправки; подписка через `/start rep_…` служит маршрутизации этой рассылки и не
  является общим разрешением читать данные через Платона или `/status`.
- Проверки: `tests/test_site_chat_owner_grants.py`, `tests/test_status_lists_every_bound_chat.py`,
  `tests/test_the_group_counter_shows_itself.py`, `tests/test_report_mailing.py`.

`team_access_allowed` (ключ администратора, ключ кабинета рынка, вход человека из команды)
по-прежнему решает «команду» для других поверхностей (например, торги), но не для монитора и
сводки.

## Демо-ссылка по разделам: что видно и что закрыто

Решение владельца 25.10.2026. Что демо-сессии можно в разделе на чтение и на запись,
решает одна функция `demo_section_problem` (`engine/review_demo.py`); её читают все
поверхности:

- монитор и сводка — демо-ссылке закрыты всегда (только ключ администратора, см. выше),
  даже если раздел в ней выбран;
- торги и рынок — `demo_request_access` (раздел и «пишет ли» по явному перечню путей),
  его зовут замок `/auctions`, замок участков Нагатино и `market_search.cabinet`
  (`require_cabinet`, `page_gate`);
- расчёт — `calc_access_for_chat`, до замка оплаты; кабинет — `_project_owner`.

| Раздел | Видно по ссылке | Закрыто всегда |
|---|---|---|
| Расчёт | расчёт как у нового клиента: один бесплатный участок, оплата тестовая | — |
| Личный кабинет | свои проекты, профиль, «Тарифы и доступ» | чужие проекты, админка |
| Монитор стройки | ничего: раздел только по ключу администратора (02.11.2026) | всё |
| Сводка руководству | ничего: раздел только по ключу администратора (02.11.2026) | всё |
| Торги и КРТ | то же, что ключу просмотра торгов (`view_access.scope_problem`): каталог, карточки, карта, выгрузка Excel; плюс вопрос Платону (`/auctions/ask`) | всё вне этого перечня: пробы источников, команды обновления (`refresh`, `force`…), сопоставление лотов (`/auctions/krt/tenders`), ответ Платона на карточке площадки (сохраняется в общий отчёт), отметки, заявки, загрузка |
| Рынок | страницы кабинета, справочники, отчёт о рынке, PDF/PPTX, вопрос Платону | запуск выгрузок, договоры, разбор планировок, пробы bnmap |

Без раздела — 403 «Эта демо-ссылка не открывает раздел «…»»; запись в разделе —
403 «…только для просмотра…»; споры — 403 с причиной. Истёкшая или отозванная ссылка не
пускает ни сессией, ни кукой («Демо-доступ по этой ссылке закончился…»).

Запись ссылки: `blocks`, `days`, `expires`, `by`, `note`, `claims`, `entries` (время
входов). Старая запись без `blocks` — прежнее умолчание: расчёт и кабинет. Журнал
(`_access_journal`): `demo_create` (кто, разделы, срок), `demo_claim` (каждый вход),
`demo_revoke`. Render узнаёт разделы у ядра тем же `/internal/demo/alive`.

Выкатка открывает данные проектов владельца по ссылке: на прод — только с решением
владельца.
