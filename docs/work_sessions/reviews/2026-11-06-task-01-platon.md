# Передача задачи 01: закрытые данные Платона и бот

Передача по [issue #1019](https://github.com/warstyle-plato/plato/issues/1019)
для исходного [PR #1015](https://github.com/warstyle-plato/plato/pull/1015).
Это авторский технический отчёт, не независимая приёмка и не допуск к выпуску.
Точные commit/tree/parent авторской ветки приведены в её записи `PLATO-HANDOFF`
в issue #1019.

## Состав результата

Функциональный результат уже находился в опубликованном коммите
`7a0c05c4f2c93173af9ceeb9185b68b2e564ec9f`, tree
`344ac43de9893a392a10a65cd4c336b1860259bc`. Этот коммит — родитель авторской
дельты; ему не приписывается новое авторство. Он меняет только тестовый
транспорт GET и проверку запрета ключа в URL. Продуктовый код совпадает с
его родителем `8ea6acd963d6a663343133bb98ae8ea2661d9a13`.

Авторская дельта добавляет только этот отчёт и
`tests/test_platon_process_isolation.py`. Четыре ранее выполненные отдельным
сценарием проверки перенесены в обычный pytest-набор без зависимости от пути
изолированной рабочей копии:

- восемь независимых процессов получают один атомарно созданный ключ подписи;
  размер ключа и права файла проверяются;
- один из восьми процессов захватывает идентификатор запроса, остальные получают
  409; содержимое и права сохранённой записи проверяются;
- отзыв разрешения группы виден следующему отдельному процессу;
- наблюдённая другим процессом смена ключа не возрождает старое разрешение
  при возврате прежнего ключа.

Все записи этих проверок находятся в `tmp_path`, данные синтетические.
Настоящие разрешения групп и источники приложения не изменяются.

## Проверки

Среда: Python 3.11.17, зависимости из `requirements-dev.txt` установлены
с проверкой хешей, Playwright 1.64.1, Chromium 156.0.8078.4.
Браузерный набор выполнялся с `REQUIRE_BROWSER=1`; отсутствие браузера
не разрешалось скрыть пропуском.

Серверный набор вместе с новыми межпроцессными проверками:

```sh
python -m pytest \
  tests/test_platon_process_isolation.py \
  tests/test_team_only_monitor.py \
  tests/test_site_chat_owner_grants.py \
  tests/test_agent_private_access.py \
  -q -rsfE --timeout=180
```

Результат: **296 passed, 0 failed, 0 skipped**.

Остальные тесты, изменённые исходным PR, и регрессии отдельной существующей
рассылки сводки выполняются следующим воспроизводимым отбором:

```sh
REQUIRE_BROWSER=1 python - <<'PY'
import subprocess
import sys

paths = subprocess.check_output([
    'git', 'diff', '--name-only',
    '17b1406ba8eb319c843b22bacf82e55a96865ff4',
    '7a0c05c4f2c93173af9ceeb9185b68b2e564ec9f',
], text=True).splitlines()
already_checked = {
    'tests/test_team_only_monitor.py',
    'tests/test_site_chat_owner_grants.py',
    'tests/test_agent_private_access.py',
}
paths = [p for p in paths if p.startswith('tests/test_')
         and p.endswith('.py') and p not in already_checked]
paths.append('tests/test_report_mailing.py')
subprocess.run([sys.executable, '-m', 'pytest', *paths,
                '-q', '-rsfE', '--timeout=180'], check=True)
PY
```

Результат: **234 passed, 0 failed, 0 skipped**. Итого **530 passed**;
четыре межпроцессные проверки входят в это число и повторно не суммируются.

Проверены действующий ключ и его смена, отказ ключу в URL, принадлежность
ответов и документов, точная группа и проект, журнал ответов, сохранение
обычного расчёта и собственных документов, интерфейс на ширинах 390/1440 px,
существующая отдельная рассылка сводки. Внешние соединения приложения
блокируются штатным `tests/conftest.py`; Telegram и модель подменены стендами.
Сырые логи и private proofs не публикуются.

## Границы передачи

- Safari, реальные отправки Telegram, клиентская первичка и живая модель
  в этом проходе не проверялись.
- Полный GitHub CI нового авторского SHA не заменяется этими профильными
  проверками. На момент подготовки передачи полный CI исходного `7a0c05c4`
  ещё выполнялся; его результат не переносится на новый SHA.
- Независимая приёмка нового коммита требуется. Старое заключение на `8ea6acd9`
  не считается допуском нового результата.

Следующий шаг существующего контроля: сверить опубликованные commit/tree/parent
и дельту, назначить независимую проверку, включить принятый результат в
существующий PR и провести полный CI на получившемся точном source SHA.
Main и общая ветка исходного PR исполнителем не изменяются; новый PR,
release approval, слияние и выпуск в этой передаче не создаются.
