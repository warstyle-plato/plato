# Пустые реквизиты платежа не образуют ключ договора

Узкое исправление действующего классификатора РСС. Строка с пустым после
канонической нормализации номером раньше могла совпасть с такой же пустой
записью реестра и получить сильное основание «по договору». Пустой контрагент
мог аналогично стать ключом. Теперь пара индексируется и используется лишь
при непустых нормализованных контрагенте и договоре; пустой контрагент не
образует и отдельный counterparty index.

Платёж без номера может по-прежнему использовать слабое сопоставление по
известному контрагенту. Однако оно не переопределяет другую однозначную
известную статью явно переданного официального crosswalk. Тогда действует
прежний fallback по коду РСС. Выведенная из реестра карта не получает новый
статус официальной. Для полностью определённых контрагента и договора
прежний порядок точного сопоставления и приоритет договора сохраняются.

Mapper и observer используют одни допустимые наборы кандидатов. Аудит не
называет отклонённую пустую пару основанием договора. Возможные статьи
официальной карты и допустимого слабого контрагента сохраняют неопределённость
строк без даты/суммы. Схема аудита сохраняется; состав классифицированных строк
может измениться для исправляемых пустых ключей.

Нет ручного вычитания платежей, удаления fingerprint-дублей, изменения
источников или их SHA, единиц, НДС, знаков/возвратов, замещения РСС фактом БДДС,
cutoff, missing/unknown или полноты истории проекта. Прежний frozen base44
oracle остаётся неизменным: валидные сценарии проверяются побайтно, а старое
сильное blank-binding отдельно сохраняется как causal oracle ошибочного
поведения. Публичные примеры полностью синтетические.

Автор не публикует, не выпускает и не выполняет реальные запросы. После
независимого review точного HEAD и CI контроль отдельно проверяет новый
результат на сохранённых источниках. Синтетические проверки не устанавливают
новые реальные суммы, состав бюджета или ошибочность банковской операции.
