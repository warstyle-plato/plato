# 1042 — подходящие договоры для сообщений о работах

Ветка исполнителя: `codex/contracts-candidates-1042`.

## Требования владельца

Сообщению конкретного подрядчика нельзя предлагать договоры всех остальных.
Надпись о предложенном соответствии должна называть реальный договор.
Счётчик учитывает уникальные строки внутри даты ежедневного отчёта. Это не
количество разных видов работ и не количество целых входящих сообщений.

## Изменения и границы

- Сервер формирует допустимые варианты и повторно проверяет новое ручное
  подтверждение по стороне, номеру, дате и полному составу корпусов.
- Страница показывает только этот список, называет единственное предложение,
  объясняет отсутствие варианта и явно называет единицу счётчика.
- Прежнее противоречащее ручное решение остаётся видимым и отзываемым, но
  не передаёт чужие договорные показатели в сводку.
- Источники, денежные формулы и данные проекта не изменяются. MS Project не
  используется. Навигация и графики Монитора относятся к отдельной #1041.

## Приёмка

Серверные контрпримеры: чужой подрядчик, похожее имя, другая юридическая форма,
номер с префиксом, будущая дата договора, неполные/неоднозначные корпуса,
несколько подходящих договоров, снятие и историческая ручная связь.
Настоящая страница в Chromium на 390 и 1440: допустимые options, явное
предложение, отсутствие фиктивного подтверждения, единица счётчика и XSS.

Проверки — синтетические данные. Частный архив владельца и Safari не
подтверждены. Авторские проверки не заменяют независимую приёмку точного HEAD.
Исполнитель передаёт локальный commit контролю; push, слияние и выпуск
самостоятельно не выполняет.

## Авторская проверка

Профиль до последнего уточнения подписи счётчика: **181 passed, 0 failed,
0 skipped**. Файлы: `test_monitor_contract_links`, `test_contract_candidate_choices`,
`test_monitor_cumulative_controls`, `test_monitor_cumulative_api`,
`test_contracts_from_cumulative_headers`, `test_cumulative_work_summary`,
`test_contracts_concise_view`. После чисто текстовой правки подписи — отдельно
**2 passed** на реальной странице при 390 и 1440.

Синтетический массовый пример: 18 записей за разные дни, несколько договоров
одной стороны по двум корпусам и договор другой стороны. 10 однозначных
записей определены автоматически; остаются 5 действительно неоднозначных и
3 без подходящего договора. Ручные решения для уменьшения счётчика не нужны.

Тестовый Python использует точные зависимости из `requirements-dev.txt` с
проверкой хешей; Chromium обязателен (`REQUIRE_BROWSER=1`). Полный CI и
независимая приёмка этим локальным профилем не заменяются.
