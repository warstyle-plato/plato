# Подтверждённое владельцем уточнение номера договора

Первый этап — отдельная поддержка на single-archive main. Второй этап —
потребитель в archive-union, который обязан использовать этот resolver.
До независимой проверки и предметной инвентаризации реальных карточек
контроль не записывает решение и не допускает экономическое объединение.

Поддержка не меняет исходные номера, raw-ID, стороны, даты, SHA, архивы,
ручные сроки, документы или прежние файлы выбора. Обычный register builder
продолжает выдавать прежние raw-карточки и суммы. Наличие записи само по себе
не объединяет денежные факты и не подтверждает финансовую полноту.

## Инвентаризация и запись

Новые POST `/monitor/contracts/identity/inventory`, `confirm`, `revoke`,
`resolve`, `result` используют текущий admin key и существующий cumulative
job store с отдельным профилем. Другие ключи и чужие job tickets не подходят.
Тело ограничено 64 КиБ до JSON-разбора, duplicate keys/nonfinite и лишние
поля запрещены. Все ответы, включая ошибки, — `private, no-store`.
Тело не принимает actor, recorded_at, пути, URL, aliases или исходные файлы.

Inventory принимает ровно два исходных ID одного сохранённого проекта.
Читает не более 32 архивов, 64 МиБ исходных ZIP суммарно, 64 версий выбранных
карточек и 16 МиБ/256 файлов метаданных привязок. Каждый исходный ZIP
проверяется по SHA и читается текущим native parser; результат не содержит
книги, финансовые строки, исходные тексты документов или соседние карточки.
Ответ содержит raw-реквизиты этих двух ID, source/archive/file/locator pins
и metadata hashes существующих terms/docs/choices/worklinks/removals.

Confirm требует revision и SHA свежей инвентаризации, весь проверенный набор
source tokens, существующий anchor ID, номер из одной из исходных версий и
основание. Обе стороны и дата должны совпасть по существующим строгим
reference rules; их raw-строки сохраняются. Номер не выбирается по сходству.
Проверка выполняется под identity lock и существующими native locks архива,
header-date, ручных сроков, worklinks и обеих документных карточек; после
повторного чтения добавляется ровно одна новая строка отдельного журнала.
Первая native загрузка документа теперь тоже соблюдает свой card lock.
Имя/root проекта закреплены в контексте операции под shared native
`.aliases.lock`; project merge использует exclusive lock. Дополнительная
проверка alias/root перед append отвергает позднюю смену пространства проекта.

Журнал append-only, ограничен 1 МиБ/256 событиями и имеет последовательность
и hash chain. Время записи — текущее UTC сервера; клиент его не назначает.
Ревокация добавляет событие, не удаляет подтверждение. Пересечения,
транзитивные цепочки, циклы, stale CAS и неподтверждённые source versions
отклоняются. Историческое уточнение не задним числом меняет источник.

## Read seam и граница объединения

`developaid_contract_identity.resolve` принимает raw-ID и cut. Без решения
возвращает `raw`; действующее проверенное решение даёт `confirmed`, общий
logical ID, оба исходных адреса, raw source versions и время позднего
уточнения. Новые/пропавшие/изменённые источники или новый непроверенный архив
дают `source_conflict` и `logical_id=None`. Отмена даёт `revoked` и `None`;
прежнее уточнение не воскресает.

Привязки обоих raw-ID возвращаются отдельно. Разные ручные сроки, редакции,
withdrawal/scan confirmations, противоречивые worklinks и choices остаются
`conflict_or_unknown`; здесь не выбирается последняя запись и не переносятся
привязки. `not_combined` означает отсутствие объединения привязок, а не
подтверждённый срок/подпись/сумму. Юридическая подпись остаётся unknown.
Каждый результат содержит `financial_acceptance=False`.

Следующий archive-union consumer должен группировать только квалифицированную
logical ownership, сохраняя все raw observations и source provenance; он
не вправе складывать повторные представления одного договора или переносить
сроки, снятия и подписи по одному совпавшему номеру. Этот consumer и запись
реального решения — отдельные действия контроля, не часть автоматического
поведения данного этапа. Публичные проверки содержат только синтетику.

## Явный выбор исправленных источников

Отдельный новый вид события и API описан в
[contract_source_corrections.md](../../contract_source_corrections.md).
Он не ослабляет прежнее подтверждение номера: реквизиты, выполнение, полная
цена и существующая карточка документов выбираются явными native tokens/ID.
Известные исходные показатели сохраняются с происхождением; отдельная
финансовая приёмка не блокирует их показ. Исходные адреса, документы, снятия,
сроки и выборы сохраняются; реальные решения и данные не входят в публичные
проверки. Запись реальных решений и выпуск остаются действиями контроля после
независимой приёмки точного HEAD.
