# B/P/L: принадлежность данных корню и закрытая диагностика структуры

Поддержка проверки размеров листа. Единственный `sheetData` должен быть
непосредственным ребёнком настоящего корневого `worksheet`. Его строки и
ячейки привязаны к тем же объектам XML и полному пути, а не только к QName
непосредственного родителя. Вложенная копия `worksheet` не создаёт область
данных для ограниченного представления листа.

При прежнем отказе `payload_namespace_unknown` необязательное поле
`namespace_structure` дополняет частный `extent_proof`. Прежняя тройка
`namespace_rejection` — `local_name`, `namespace_uri`, `truncated` — сохраняет
свой контракт, включая предел URI в 256 байт UTF-8. Старые сообщения без нового
поля продолжают проверяться прежним способом.

`path` содержит не более 12 токенов начала наблюдённого пути, включая текущий
узел, `depth` — полную наблюдённую глубину, `truncated` явно отмечает пропуск
хвоста. Поле `other` отмечает неизвестный QName во всём пути, включая пропущенный
хвост. Известные токены главного пространства SpreadsheetML: `worksheet`,
`sheetData`, `row`, `c`, `v`, `f`, `is`, `extLst`, `ext`. Закрытые сокращения
Office2010: `x14:cfs` — `conditionalFormattings`, `x14:cf` —
`conditionalFormatting`, `x14:rule` — `cfRule`, `x14:bar` — `dataBar`,
`x14:cfvo` — `cfvo`; `xm:f` обозначает формульный узел OfficeExcel2006.
Все остальные QName становятся токеном `other`; их имена и URI из пути
не экспортируются.

Вектор `checks` использует только состояния `match`, `no_match`,
`not_evaluated`. Он описывает прежнее исключение для формульного порога
Excel2010 в прежнем порядке: `path`, `data_seen`, `row_inactive`,
`cell_inactive`, `attributes_empty`, `first_child`, `cfvo_formula`,
`rule_data_bar`, `rule_guid`, `extension_attributes`, `extension_uri`.
`first_unmet` называет первое несовпадение; последующие проверки не выполняются.
Общий помощник при всех совпадениях возвращает `none`; в отклонённом
`namespace_structure` этот результат недопустим и отбрасывается вместе с
`extent_proof`. Атрибуты предков читаются только
после совпадения полного QName-пути и предыдущих условий. Boolean-решение
исключения и диагностика используют один проверяющий код.

Новые сведения не расширяют принимаемые пространства имён, типы порогов
или пути метаданных. Неизвестный или сокращённый путь не подтверждает
совместимость. Текст формулы, значения ячеек, произвольные атрибуты, пути
файлов и исходный XML не попадают в новые поля. Состояния, длины и согласованность
вектора проверяются закрытым валидатором. Весь прежний частный failure envelope
по-прежнему ограничен 2048 байтами; публичная успешная схема и финансовые
признаки не меняются.

Синтетические проверки закрепляют отказ вложенной области, настоящую
принадлежность объектов, прежнее исключение, канарейки, конкурентные вызовы,
границы диагностики, ограничения содержимого и полный EOF/CRC. Реальная
приёмка сохранённых источников остаётся отдельным этапом после независимого
допуска и штатного выпуска; этот патч её не выполняет.
