# Служебное чтение сохранённых исходных КС

Назначение контроля: отдельно разблокировать предметную проверку уже
сохранённых Excel до допуска автоматических изменений выбора источников.
База: core `8fee3c22`. Это read-only поддержка существующего контроля.

Добавлен фиксированный `/monitor/contracts/source-review` через текущие
admin auth и native background jobs. Вход — проект, дата среза, стабильный
id существующей карточки и native ticket/auth. Strict body запрещает
произвольные пути, файлы, листы, диапазоны, URL и другие селекторы.

Читаются только retained cumulative archives выбранного проекта. Сервер
проверяет SHA ZIP, выбирает книги/листы через штатный parser и проверяет SHA
самой книги. Совпадение требует существующий точный original contract
identity: номер, известная дата, заказчик и подрядчик. Никаких aliases или
ослабления даты нет; неоднозначная идентичность прекращает проверку.

Ответ содержит только raw периоды/номера актов/исходные значения своей
карточки и ограниченные ячейки её заголовков. В сводной возвращается своя
секция; из общего preamble — лишь фиксированные названия колонок.
Соседние суммы и общие итоги не возвращаются. Размеры входа, архивов,
сопоставленных источников, строк, периодов, ячеек и ответа ограничены.
Source drift — отказ. Недоступная первичка — явная неполнота; пустой список
датированных фактов не объявляется доказательством отсутствия дат в Excel.

Номерной writer и его API/UI, aliases, retention, перегруппировка договоров,
источники проектного ГПР и финансовые расчёты не включены. Исходные файлы,
факты, даты и связи не меняются, модельные запросы не выполняются. Обычные
страницы этот служебный маршрут автоматически не вызывают.

Проверка: 338 passed, 0 skip — raw source-review и полный профиль
`test_team_only_monitor.py`. Native API, текущий admin gate, строгий body,
чужие стороны/даты/номера, недоступный оригинал, SHA/drift, старые версии,
границы своей секции и лимиты проверены на синтетических источниках.
Реальное чтение первички остаётся контролю после независимой проверки
этого HEAD, CI и штатного выпуска; локальные тесты его не подменяют.

Исполнитель не публикует PR, не выпускает приложение и не обращается к
production API. Частные реквизиты, документы и суммы не включены в ветку.
