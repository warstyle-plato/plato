# Договоры: карточка в окне и единое сравнение плана с фактом

Исполнитель: Codex, по поручению действующего контроля Codex. База:
`c2478a48df6b86e03e4fb68ebec8db0526d6e826`. Ветка:
`codex/contract-modal-comparison-20261113`. Выпуск и prod здесь не выполнялись.

## Соответствие поручению и ТЗ

ТЗ «Контроль сроков по договору подряда» требует сопоставить накопленные с начала
работ план и факт на дату, разложив позиции РДС/КС на работы ГПР; редакция ДС меняет
действующие условия, а выполнение датируется периодом работ. Центральная таблица
теперь одна: работа/единица, план на дату, факт, отклонение, срок и прогноз.
Серверная проекция читает готовые `control`, `plan`, `fact`: натуральный объём
при наличии сопоставимой единицы; стоимость с явной подписью при отсутствии такой
единицы. JS только форматирует и фильтрует готовые значения. Новых расчётов денег,
сроков, связей или общепроектного ГПР нет.

Кнопка, стрелка и строка реестра открывают один native dialog. Вверху цена,
договорный срок, прогноз и выполнение плана; далее сравнение на выбранную дату.
Списки долгих driver/overdue работ заменены строками и фильтрами. Источники,
методика, денежные наблюдения, исходная КС-6а и документы закрыты. Каждый документ
отдельно закрыт; его условия, РДС, ГПР/акт имеют нумерованные закрытые подразделы.
Длинная инструкция чтения документов также закрыта. На телефоне одна вертикальная
прокрутка окна. Основной текст 14px, подпись 12px; горизонтального выхода нет.

Наличие исходного ГПР не требует наличия факта: проекция сохраняет все конечные
работы выбранного документа с точным SHA. Несопоставленные работы показывают
известный срок и неизвестный объём/факт с конкретной причиной. Неизвестное не равно
нулю. Покрытие «N из M работ» и частичность видны над таблицей; сопоставленная
область не называется готовностью всего договора. Сохранены явные родительские
контексты работ; совпадение кода/имени не используется для выбора документа.

## Доступ, печать и композиция

Закрытие, Escape, смена проекта/даты/ключа и отказ доступа закрывают окно и стирают
содержимое/значения форм. Поздний ответ закрытую карточку не восстанавливает.
Фокус возвращается на кнопку/стрелку выбранной строки. Открытая карточка печатает
текущее сравнение, закрытая — реестр. В печати реестра сохранены business поля всех
договоров отдельным print summary; это не старая скрытая интерактивная карточка.
Чат, технические файлы, ключи, документы и управляющие формы не печатаются.

Стабильные upload IDs/handlers сохранены: `contractDocumentFile`,
`contractDocumentUpload`, `contractKs2Upload`, `contractKs2File`,
`contractDocuments`, `contractDocumentsMsg`; КС-2 по onchange. Для параллельного
Excel reader оставлен guarded hook `contractExcelPositionsHtml`. Для report-check
оставлены `contractReportSignalAction` и `.contract-report-check` binding.
Самого report handler в базе нет: при композиции его reload должен условно
переоткрывать только ещё выбранный exact id/context/generation. Закрытая владельцем
или сменённая карточка переоткрываться не должна. Это проверяется на композиции.

Метаданные выбранного графика: `_editions.schedule_sha256` →
`plan.editions[].schedule_sha256` → `comparison.coverage.schedule_sha256`.
При композиции bundle/source-retention патча нужно сохранить его выбор действующей
редакции, добавив это поле к выбранному объекту; не заменять его прежним reader.
Согласованные внешние дельты reader/денежной VAT policy этим патчем не меняются.

## Реальные сохранённые данные

Локальный readonly replay существующих источников, без новых загрузок и prod
записей, выполнен в реальном PAGE на 390 и 1440px. Частные receipts/screenshots
сохранены вне Git в каталоге исходников владельца. Случаи:

- 140 конечных работ из 151 исходной строки: 44 сопоставлены; 96 с неизвестным
  фактом сохраняются в таблице. Это не 44 работы всего договора.
- 46 конечных работ из 62 исходных строк: 29 сопоставлены; 17 с неизвестным фактом.
- 35 конечных работ из 41 исходной строки принятого bundle: известный план у 35,
  факт у 35 неизвестен. Заголовки не названы отдельными работами.

Третий replay использует принятый bundle receipt с одним явно выбранным графиком;
снимок API предшествовал новому полю SHA, поэтому SHA добавлен к его единственному
выбранному документу только в стенде. Native plan/fact/control заново не изменены.
Полный source-retention другой ветки принимается отдельно. Синтетические снимки
без частных данных: `/workspace/artifacts/contract-modal-comparison-20261113/`.

## Изменение проверок

Старые inline helpers/селекторы переведены на видимое окно и явное раскрытие
источника. Скрытой старой карточки ради тестов нет. Сохранены точные значения цены,
НДС, основания процента, остатков/оплат, дат, native объёмов и периодов выполнения.
Проверки обычной короткой строки (80px desktop), доступа и реальной PDF печати
реестра не ослаблены.

Устаревшие UI assertions заменены предметно:

- Отдельные строки план/факт/контроль → одна строка с теми же 0,5 / 0,313 /
  −0,188 м3, −37,5%, 62,5%, просрочкой и прогнозом 06.02.2026.
- Отдельная месячная таблица → смена среза 28.02/02.03 в этой же таблице, сохранив
  native денежный план 11 000 и факт 0/2 000, натуральный факт 0/0,094 м3.
- Исходный накопленный план 7 000 из 11 000 сохранён в закрытом scalar audit;
  прежний отдельно рассчитанный в JS процент 63,6% больше не выводится. Новый
  процент поверх native amounts не придуман. Проверяются native суммы и единица.
- 3 отдельные таблицы/их число больше не требуется; вместо них проверяется одна
  главная таблица и сохранённые исходные РДС/ГПР/связи/КС в закрытых источниках.
- source-only отсутствие прогноза явно проверяется в плашке и каждой строке;
  существующий прогноз 06.02.2026 проверяется точно, без generic утверждения «ГПР».
- Печать реестра вызывается после закрытия окна; отдельно проверяется печать
  текущей карточки. Суммы/основания процента в реестре остаются видимы на печати.

Профили и окончательный SHA дополняются после финального targeted прогона.

работы остаются в таблице с точным SHA и причиной; ambiguity/future/removed/
unconfirmed/unknown binding не выбираются. Достижимость проверена настоящим
synthetic PDF → reader → store → listing и браузером 390/1440.

Последние privacy проверки: A/B/A не накапливает обработчики и старые id на
постоянном host, close стирает onclick; явный ручной срок сохраняет и своё значение,
и подпись источника при ответе с документным сроком. Финальный real replay трёх
сохранённых комплектов сохранил указанные выше 140/44, 46/29, 35/35 с unknown
фактами, без JS ошибок и горизонтального выхода. Репозиторий не содержит его
частных данных или снимков.
