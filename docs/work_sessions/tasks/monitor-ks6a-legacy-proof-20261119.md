# Монитор: приёмка сохранённых редакций КС-6а после выпуска

Продолжение поручения по основной КС-6а и копиям ведомостей, PR #1209.
Исходная база `6493aeb6d4ff39306093b572a99184c3da0354c3` (0.30.18), ветка
`codex/monitor-ks6a-legacy`, отдельный worktree.

## Обнаруженный блокер

Независимая локальная приёмка трёх побайтово подтверждённых текущих загрузок
и полный CI прошли. Однако обязательная проверка рабочей карточки после
выпуска сохранила 43 непрочитанные работы при объединении с прежней книгой.
План, документы и состав КС-2 не изменились; новая логика честно сохраняет
неопределённость, ложных нулей и процентов нет. Общая проверка прода этот
предметный блокер не заменяет. Задача не объявлена завершённой.

По доступным исходным полям прежней книги все известные движения покрыты
текущей, но сокращённый DTO не содержит всех полей определения семейства
и фактического состояния сохранённого parser metadata. Точная причина
отказа семейства по этим DTO не выдумывается. Частные значения и ответы API
хранятся вне Git.

## Локально доказанные классы дефектов

- `read_snapshot` признавал manifest текущим по schema и основаниям НДС,
  без отпечатка кода и зависимостей parser. Теперь актуальность source parser
  проверяется отдельно; старый результат обновляется только из проверенного
  по SHA оригинала, без перезаписи manifest и прежних `li:ii`.
- Сохранённые индексы могут давать порядок `items`, отличный от порядка
  исходных строк. Для доказательства совпадения и покрытия используется
  отдельный индекс по уникальным координатам листа/строки. Исходные массивы,
  контекст и привязки не переставляются; неоднозначные координаты не дают
  доказательства покрытой версии.
- Устаревшие сведения при недоступном оригинале не получают новое
  доказательство семейства. Контекст, план, единицы, источники, известные
  движения и нулевые компоненты по-прежнему проверяются строго.

Эти классы ошибок подтверждены независимыми контрпримерами, но их связь
с конкретной сохранённой книгой пока не выдана за установленный факт.
Перед предметной приёмкой нужны полные разрешённые исходники либо точные
результаты guard-проверок фактически используемых четырёх ledger.
После установления причины обязательны replay через `read_snapshot`,
независимая приёмка точного source HEAD, полный CI и повторная проверка
рабочей объединённой карточки.

Локально проверены 123 сценария с обязательным Chromium, без пропусков.
Три реальные текущие книги также проиграны через `store_archive` и
`read_snapshot` в новых локальных ZIP: отсутствие fingerprint и перестановка
сохранённых индексов не меняют исходные привязки, manifest и результат.
Это регрессия пути чтения, не воспроизведение недоступного старого server
manifest. Патч не публикуется как установленное исправление Сталко до
фактических guard outcomes. Для них подготовлен отдельный наблюдательный
PR #1210, не меняющий расчёты.
