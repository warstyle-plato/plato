# DevelopAid Desktop — первая рабочая версия

Разработка ведётся в `codex/developaid-desktop`. В `main` ничего не сливается,
production не разворачивается. Серверная часть изменения — только публичный
GET `/api/desktop/reference-pack` с явно перечисленными справочниками.

## Что работает

- Белый и графитовый интерфейс без зелёных акцентов. Три раздела как на сайте:
  «Проект» (ТЭП, очерёдность), «Экономика» (вводные и раскрываемое подменю
  «Отдельные объекты»), «Результат» (отчёт и денежный поток). Переход между
  шагами кнопками «Назад» / «Далее» и свободно через меню.
- Рабочее пространство для компьютера: список проектов, таблицы параметров,
  постоянные KPI, результат, помесячный денежный поток и история версий.
- Расчёт без интернета тем же `_run_authoritative_model`, который использует
  сайт. Формулы не продублированы в JavaScript и не изменены.
- SQLite хранит проекты, неизменяемые снимки вводных, результата и исходного
  расчётного bundle, версию движка и связанную версию справочников.
- Открытие проекта показывает сохранённый результат без пересчёта. Повторное
  сохранение создаёт запись истории; устаревшее окно не затирает свежую версию.
- PDF получает сохранённый bundle. Книга Excel использует существующий
  шаблон с формулами и финансовыми подсказками из того же bundle. Ошибки
  переноса полей в книгу не скрываются.
- Выгрузка JSON и открытие его вводных на другом компьютере. Импортированные
  вводные рассчитываются текущей версией; чужие готовые цифры не принимаются
  за результат местного движка.
- Проверка обновлений скачивает общие профили классов и реестр источников.
  Пакет проверяется и сохраняется одной транзакцией. При обрыве сети остаётся
  последняя пригодная копия. Применение профиля показывает изменения и создаёт
  отдельный сценарий; сохранённые проекты обновление не переписывает.
- Сочетания Ctrl/Cmd+S и Ctrl/Cmd+Enter.

## Запуск из исходников

Python 3.12. Команды из корня репозитория:

```sh
python -m venv .venv
# macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-desktop.txt
python -m desktop
```

Для проверки без нативного окна: `python -m desktop --browser`.
Откроется локальное приложение; завершение процесса — Ctrl+C в терминале.
Движок никогда не публикуется в локальную сеть: слушает случайный порт
`127.0.0.1`. API защищён одноразовым токеном процесса, проверкой Host/Origin;
маршрутов Telegram, административного API и серверных фоновых задач здесь нет.

## Где лежат проекты

- macOS: `~/Library/Application Support/DevelopAid/developaid.sqlite3`.
- Windows: `%LOCALAPPDATA%\DevelopAid\developaid.sqlite3`.
- Linux для разработки: `~/.local/share/DevelopAid/developaid.sqlite3`.

`DEVELOPAID_DESKTOP_DATA` позволяет выбрать другой каталог для тестов.
Данные не лежат внутри `.app`/папки программы и переживают замену приложения.
Для полной резервной копии закройте приложение и скопируйте SQLite-файл;
для переноса отдельных вводных используйте JSON-выгрузку.

## Обновление базы

Адрес зафиксирован: `https://developaid.ru/api/desktop/reference-pack`.
До отдельного принятия и развёртывания серверного GET приложение работает на
встроенной базе; кнопка обновления честно сообщит, если endpoint ещё не доступен.
API не принимает проекты и не возвращает пользовательские данные или ключи.

Пакеты привязаны к точной версии движка: новая версия, меняющая смысл поля,
не должна незаметно применяться к старой программе. Изменения цен/профилей в
рамках этой версии могут обновляться независимо. Реестр нормативов — описание
источников, а не загружаемый исполняемый код: формулы нормативов обновляются
только с приложением. SHA-256 проверяет целостность; подлинность транспорта
обеспечивает HTTPS, отдельной цифровой подписи пакета в этой версии нет.

## Сборка и проверки

Для первого теста на MacBook Apple Silicon подготовлен отдельный workflow
`desktop-macos-preview.yml`: запускается после отправки ветки
`codex/developaid-desktop`, без PR или слияния. Использует macOS 14 / ARM64,
проверяет архитектуру, целостность подписи и расчёт с PDF/Excel внутри
готового `.app`. Только после успешной проверки выдаёт
`DevelopAid-MacBook.zip` и SHA-256. Это пока конфигурация сборки, а не
подтверждение её выполнения на Mac.

У workflow только право чтения репозитория; он не разворачивает сайт.
Проверка `codesign` проверяет подпись упаковщика (ad hoc), а не Apple
Developer ID или notarization. Для обычной установки без предупреждений
Gatekeeper нужна отдельная подпись релиза.

```sh
python -m pytest tests/test_desktop.py -q
python -m desktop --smoke
python -m PyInstaller --noconfirm --clean desktop.spec
```

Workflow `desktop-build.yml` собирает Windows x64, macOS Apple Silicon и
macOS Intel. В каждом случае запускает **упакованное** приложение с `--smoke`:
реальный расчёт, PDF и Excel. Только после этого публикует архив как artifact
конкретного запуска Actions. Архив Mac сохраняет права через `ditto`.
В Windows нужен WebView2 Runtime для окна pywebview.

Проверка GUI в браузере:

```sh
python -m playwright install chromium
python scripts/desktop_ui_smoke.py
```

Она проверяет ввод → расчёт → сохранение → перезагрузку → открытие с теми же
KPI, просмотр изменений базы, историю и скачивание JSON. Скриншот сохраняется
в `docs/desktop-preview.png`. Для уже установленного Chromium можно указать
`DEVELOPAID_TEST_CHROMIUM`.

В приложение входят только выбранные публичные данные, шаблон Excel, шрифты
с лицензией и ресурсы интерфейса. `.env`, пользовательские каталоги и весь
рабочий `data/` в сборку не копируются. Для цепочек формул большого Excel
в desktop-процессе установлен лимит рекурсии 10000; проверка циклических
ссылок остаётся в существующем вычислителе.

## Границы этой версии

Это проверяемый первый вариант, не подписанный релиз для широкой установки.
Подпись Windows, Apple Developer ID/notarization, установщики и автообновление
приложения ещё не настроены. Нативные диалоги и загрузки должны быть проверены
на реальных Mac/Windows; headless-smoke не заменяет такую проверку.

Облачная синхронизация личных проектов, вход через Telegram, ИИ, рынок и поиск
КРТ/торгов в эту локальную оболочку пока не подключены. PDF/Excel доступны для
снимков текущей версии движка; старые снимки всегда можно открыть и выгрузить
в JSON. Редактор очередей задаёт общие доли продуктов; расширенные абсолютные
ТЭП очередей из импортированных данных сохраняются, но отдельного редактора
для них здесь пока нет.
