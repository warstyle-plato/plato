# Решение владельца о банковском отнесении АХР

Это классификация выбранных денежных строк финансовой модели. Суммы берутся
из проверенных источников месячных формул; XLSX не переписывается. Решение
не подтверждает лимит банка, покрытие статьи или её недостаток средств.

## Частное хранение и привязка

В проекте сохраняются append-only события `finance_allocations/<revision>.json`:
`source_sha256`, `revision`, выбранные `row_id`/`bank_code`, `recorded_at` в UTC,
`actor=administrator`, `basis=owner_instruction` и обязательная audit-note.
Эти события и рабочие payload находятся в частном хранилище, вне репозитория.

`row_id` связан с SHA прочитанных байтов, листом, строкой и колонками суммы и
банковского кода. Выбирать разрешено только ячейки ФАКТА АХР, денежные источники
которых сверены и исходный банковский код которых действительно пуст.
Непустые коды, ошибки вместо пустой ячейки и неподтверждённые суммы не исправляются
этим каналом. Денежных полей в решении нет; лишние поля запрещены.

Смена файла снимает применимость решения. При снятии или изменении решения
пишется следующая ревизия; `bank_code=""` отзывает отнесение выбранной строки.
Исторический cut не видит более поздних решений. Повреждённый аудит не открывает
старое решение: ручное отнесение не применяется, известный бюджет сохраняется.

Проверка SHA/ревизии, денежных источников и запись события происходят под
process-shared lock. Штатная замена финансовой базы использует тот же lock.
Дополнительный SHA fence защищает от внешней замены файла, обходящей этот путь.
Кэш производных значений связан с SHA и содержимым применимых решений.

## Admin-only API

`POST /monitor/finance-allocation/view` принимает `project`, `cut`, текущий
административный `key` и при необходимости `session`. Только ключ администратора
открывает данные; кабинет рынка, Telegram/team или одна session не заменяют его.
Все ответы имеют `Cache-Control: private, no-store`.

`POST /monitor/finance-allocation/apply` принимает те же поля и:

```json
{
  "source_sha256": "<SHA текущей финансовой модели>",
  "revision": 0,
  "assignments": [{"row_id": "<ID конкретной строки из view>", "bank_code": "2.6"}],
  "note": "Основание и решение владельца о выбранных строках"
}
```

Обработка Excel проходит в существующем фоновом job service. Ответ `202`
содержит ticket; результат читается через `POST /monitor/finance-allocation/result`
с теми же полномочиями. Повтор одного admission ticket не повторяет запись.
У завершённого результата необходимо проверить `ok`: конфликт SHA или ревизии
возвращает `ok=false, status=409`, даже если HTTP получения результата успешен.
Ключ и session не сохраняются в worker payload или audit.

## Каноника и представление

Источник суммы остаётся формулой/денежной ячейкой. `bank_code_origin` отдельно
показывает `workbook` либо `owner_instruction`, а owner decision сохраняет
actor, ревизию и основание. Общие B, оплаты, доступный лимит и gap не меняются
от переклассификации. Монитор и HTML/PDF читают одну таблицу АХР; текст кратко
помечает банковское отнесение по решению владельца.

Стоимость АХР и их будущий план не назначаются недостатком средств. Разбивка
общего gap на стройку/накладные требует сопоставимых сумм покрытия этих частей
либо отдельной явной пометки оценки владельца. Неполный график не уменьшает B
и не скрывает известный общий B/P/L-расчёт.
