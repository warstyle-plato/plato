# Общая готовность по подтверждённому составу

Сводка читает тот же `primary_fact`, что и полоса работы в Мониторе: показатель
из ГПР или явно сопоставленные натуральные объёмы КС со своей датой. Например,
при показаниях ГПР 80% и сопоставленной ведомости 40% первичный факт остаётся
40% по ведомости; ручное показание ГПР не выводится рядом как второе выполнение. Оплата, денежное
закрытие и общий процент непривязанного раздела КС в готовность работы не входят.

Общий показатель — сумма `вес × выполнение`, делённая на сумму полных весов
объявленного состава. Стоимость СМР — предпочтительное фактическое основание.
Допускается отдельный явно оценочный профиль долей строительных элементов с
названием, источником, типом здания и границами применения. Сметные и оценочные
веса не смешиваются. Нет равных весов работ или корпусов по умолчанию.

Исторический [документ СИС от 06.05.2019 № РС-ПГ-139/19](https://smetnoedelo.ru/upload/iblock/780/RAZYASNENIE-SIS-O-raschete-stroitelnoy-gotovnosti.pdf)
описывает суммирование готовности конструктивных элементов с удельными весами.
Это основание для формы оценочного профиля, а не автоматически принятая таблица
для любого здания. Принятый владельцем оценочный профиль хранится в `developaid_schedule_elements.py`; он не применяется к работам по совпадению названий. Показатель для специальной
цели раскрытия эскроу не объявляется общим физическим процентом проекта.

## Полный знаменатель

Профиль привязан к одному сохранённому `full_schedule` источнику, его полному
отпечатку состава и текущему SHA/ревизии остаточного ГПР. Архивы не объединяются
в знаменатель. Сервер сам извлекает определения работ из сохранённых файлов;
клиент передаёт идентификаторы, а не исходные строки или файловые пути.

Точные уникальные `physical.definition` сопоставляются автоматически. В
`crosswalk` перечисляются только исключения переименования/перенумерации.
Неоднозначное соответствие и перенос между корпусами не принимаются. Общий
элемент с несколькими работами требует подтверждённого распределения его веса;
название элемента не раздаёт одинаковый процент или вес всем работам группы.

`included_ids` и `excluded_ids` без пересечений покрывают выбранный полный
источник. `construction` означает готовность объявленного строительного состава;
остальные проектные, разрешительные и закупочные пакеты остаются явно вне этого
показателя и видны в обычном ГПР. Их нельзя молча усреднить с конструкциями.
`gpr_all` означает весь состав ГПР и иначе подписывается в сводке.

Решение «работы вне остаточного перечня завершены» сохраняется только для
известных `outside_completed_ids` выбранного полного состава, связанных с
конкретным remaining SHA. Предварительный просмотр возвращает точный список
кандидатов для проверки. Сохранение требует этот список и основание владельца.
Решение имеет собственные `recorded_at` и `effective_from`, не превращается в
фактическую дату окончания и не применяется к прошлому срезу. Более позднее
противоречащее показание снимает возможность безоговорочного процента.

## Проверка и сохранение

Закрытые `/monitor/readiness/profile-preview` и `profile-save` используют
штатную авторизацию администратора. Операции не загружают книгу. Предварительный
просмотр ничего не применяет. Сохранение проверяет SHA профиля и ожидаемые
ревизии профиля/ГПР под общей блокировкой, дописывает историю и не меняет исходники.

Ниже **синтетический пример**, не профиль реального проекта или нормативные доли:

```json
{
  "project": "Synthetic readiness",
  "expected_source_sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "expected_source_revision": 1,
  "expected_revision": 0,
  "configuration": {
    "label": "Учебный профиль",
    "scope_kind": "construction",
    "scope_note": "Подтверждённый учебный строительный состав",
    "basis": "estimated_elements",
    "source_reference": "Учебная экспертная оценка",
    "building_type": "Учебное здание",
    "full_source_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "effective_from": "2026-11-12",
    "full_scope_confirmed": true,
    "included_ids": ["1", "2", "3"],
    "excluded_ids": [],
    "outside_completed_ids": ["1"],
    "owner_note": "Учебное подтверждение конкретной работы вне остатка",
    "crosswalk": [],
    "weights": [
      {"full_id": "1", "value": 60},
      {"full_id": "2", "value": 20},
      {"full_id": "3", "value": 20}
    ]
  }
}
```

Дату выбирают текущую или будущую. В `profile-save` передают тот же запрос и
`expected_profile_sha256` из просмотра. Для `smr_cost` каждый вес содержит полную
`value` стоимости СМР, `planned_cost_split: true`, `basis` НДС, `valuation_key`
источника и уникальные `position_keys`. Повтор позиции в разных работах
блокируется, материалы не добавляются к весу монтажа.

Частичный набор весов может сохранить подтверждённый состав, но не даёт общего
процента проекта. Полностью обеспеченный корпус сохраняет собственный расчёт;
неизвестный вес другого корпуса его не обнуляет. Внутри неполного корпуса
известная часть не нормируется за весь корпус. Неизвестное показание даже с
нулевым весом не превращается в ноль/100% и не даёт безоговорочной готовности.

Без действующего профиля сводка остаётся компактной: причина, текущий остаточный
состав, counts и даты; детали по корпусам раскрываются. Она не воспроизводит
пустую матрицу и не блокирует Гант или КС. Отсутствие профиля, весов, показания,
сопоставления и конфликт источников имеют разные причины.

корпуса без отделки квартир. Это экспертный стартовый профиль, а не значения
нормативной таблицы СИС. Он не является глобальным умолчанием приложения.

Общий паркинг требует отдельного профиля. Таблица сама не сопоставляет строки
ГПР с элементами: закупка и монтаж не получают дважды один физический вес;
процент остаточной части не переносится на весь ранее начатый элемент.
При нескольких работах внутри элемента необходимы явные внутренние доли или
полные сопоставимые сметные веса. Без такого распределения число блокируется,
а известные показания и counts остаются видимыми. Позднее уточнение по смете
сохраняется новой версией профиля с историей. Действующий production-профиль
этим документом не создаётся.


## Матрица и редактор

Над Гантом находится матрица «этап × корпус»: процент по известным данным,
покрытие веса, количество учтённых работ и дата самого старого использованного
показания. Неполное число явно подписано; рядом перечислены неизвестные элементы,
сопоставления, внутренние доли и показания. Процент больше 100% ограничивается
100% при агрегировании, но не создаёт дату завершения.

В «Долях видов работ» администратор выбирает уже сохранённый полный ГПР,
подтверждает тип каждого корпуса и явно сопоставляет работы элементам.
Несколько работ одного элемента требуют внутренних долей с суммой 100%.
Одна работа получает весь вес элемента. Название строки никогда не создаёт
сопоставление. Паркинг помечается отдельным составом и не получает жилые доли.
Подтверждение полного состава и завершения работ вне остаточного перечня
остаётся явным решением; до него можно сохранить черновик без общего процента.

Ручные доли накладываются на текущий каталог, хранятся в версиях
`readiness_profiles.json` под межпроцессной блокировкой. Отсутствующий override
означает оценку из каталога; явный ноль — ручное исключение веса. Пустой ввод
не сохраняется нулём. Сумма 90% или 110% допустима и показана без подгонки;
проценты нормируются по весам использованных показаний. Возврат удаляет override
новой версией, сохраняя историю, автора и дату. Предварительная проверка и
сохранение проверяют прежнюю ревизию; конкурирующая запись возвращает 409.

`/monitor/readiness/editor` и прежние preview/save закрыты действующим ключом
администратора. Страница после сохранения запрашивает общий расчёт; Монитор,
сводка и PDF читают один `schedule.readiness`, а не вычисляют процент отдельно.
Реальный проектный профиль этим кодом автоматически не подтверждается.

Таблица выше генерируется из каталога: `python scripts/gpr_profile_doc.py --write`.
Проверка соответствия: `python scripts/gpr_profile_doc.py`.

### Общая готовность нескольких корпусов

Одинаковые оценочные доли разделов не означают одинаковый размер корпусов.
В общей готовности несколько корпусов взвешиваются по их полному сопоставимому
плану, сохранённому в исходных показателях работ. Для стоимости СМР обязательны
одни уровень цен и база НДС; натуральный объём допустим только для одного вида
однородных работ в одинаковых единицах во всём объединяемом составе. Пропуск,
неполный план, разные основания или повтор конечной позиции не заменяются
равными долями: общий процент и его покрытие тогда неизвестны. Проценты
отдельных корпусов и матрицы сохраняются со своими ограничениями.

Сначала внутри раздела распределяется его оценочная доля по полным показателям
работ. Затем при объединении корпусов каждая такая доля умножается на долю
полного плана своего корпуса в общем плане. Плановые суммы используются один
раз для определения масштаба корпуса; они не прибавляются к оценочным долям.
Например, готовые работы корпуса с полным планом 100 млн и незавершённые работы
корпуса с планом 1 млн дают 100/101 общей готовности, а не 50%. Изменение
оценочной доли раздела по-прежнему действует внутри каждого корпуса; изменение
полного плана корпуса меняет его вклад в общую готовность. Число строк и
дробление одной работы не определяют ни один из этих весов.

## Экспертные внутренние доли

Внутренние доли допускают экспертную оценку, если точная сметная разбивка
не нужна. В редакторе выбирается «Экспертная оценка» и задаётся процент
каждой работы внутри раздела и корпуса. Сумма должна быть 100%; пустые
доли не заменяются равными. Доли разделов МКД из каталога сохраняются.

Экспертные проценты хранятся в существующем `share` без фиктивной стоимости,
документа или подтверждения сметы. Метка «Экспертная оценка внутренних долей»
видна в общем расчёте, сводке/PDF и истории профиля с автором и датой.
В одном элементе оценочные проценты не смешиваются со сметным расчётом;
при смене основания старые поля очищаются.

При дроблении работы её исходная доля делится между подзадачами. Например,
основной монолит сохраняет 95%, а все мелкие работы вместе — 5%, независимо
от того, представлены они одной строкой или двадцатью. Сметные данные можно
добавить позднее. Экспертная оценка долей не подтверждает полноту выбранного
перечня работ или факт выполнения: эти сведения сохраняют свои основания.

## Внутренние веса по полному плану

Доли разделов МКД из каталога сохраняются. Количество строк ГПР не определяет
долю работы внутри раздела. Разнородные работы взвешиваются по полной плановой
стоимости СМР; однородные работы одного вида допускают проектные объёмы в
одинаковых единицах. Оплаты, авансы, суммы принятых КС и остаток средств на
завершение не заменяют полный план.

Внутреннее распределение использует полный состав элемента, включая ранее
завершённые работы, сопоставленные с действующим остаточным ГПР. Остаточный
перечень не становится новым знаменателем. Например, при полных стоимостях
19 млн и 1 млн веса остаются 95% и 5%, даже когда первая работа завершена.
Дробление второй работы на 20 строк сохраняет её совокупный вес 5%.
Это синтетический пример, не смета реального проекта.

У соответствия работы есть необязательный `weight`:

```json
{
  "element_id": "frame",
  "share": null,
  "weight": {
    "basis": "smr_cost",
    "value": 19000000,
    "unit": "RUB",
    "source_reference": "Синтетическая полная смета, лист СМР, строка 38",
    "valuation_key": "Синтетическая смета v1, единый уровень цен",
    "cost_basis": "without_vat",
    "position_keys": ["synthetic-estimate-v1:leaf-38"],
    "full_scope": true
  }
}
```

Для `planned_quantity` указывается фактическая единица натурального плана,
а `valuation_key` явно подтверждает один вид однородных работ. Денежные единицы
в таком режиме не принимаются. В одном элементе нельзя смешивать стоимость
с объёмами, разные единицы/виды операций, базы НДС или уровни цен. Источник и
полнота плана обязательны; неполный черновик сохраняется без расчётного веса.
Пустое значение остаётся неизвестным, а не нулём. Нулевой вес незавершённой
работы не подтверждает готовность всего состава.

`position_keys` обозначают отдельные конечные позиции источника с версией и
объектом. Одну позицию нельзя повторить у разных работ или корпусов. Для
родительского пакета перечисляются его конечные позиции: включение того же
дочернего объёма в другую работу блокирует обе претензии на вес. Итоги вместе
с дочерними строками не суммируются.

Редактор показывает исходный полный план, документ и позиции, базу НДС/цен,
подтверждение полноты и рассчитанную сервером внутреннюю долю. Исходные значения
и основания сохраняются в журнале профиля. Ранее сохранённые явные проценты
доступны для редактирования как экспертная оценка; автоматического
распределения поровну нет.
