# Чтение ГПР в срезе Монитора

Полный срез и каждая точка тренда используют установленный `monitor.build`:
финансовые слои и единый расчёт денег не заменяются облегчённой копией.
Тренд берёт только снимки РСС не позже выбранной даты.

В одном согласованном чтении одинаковые байты корпусного ГПР разбираются
один раз. Ключ — SHA256 содержимого, результат — только чистый разбор файла,
до назначения проектной даты, области плана или квалификации факта.
Каждый потребитель получает собственную копию из неизменных JSON-байтов.
Кэш ограничен восемью исходниками и 16 МиБ, живёт только в контексте
`approved_schedule_read` и удаляется в том числе при исключении.
Между запросами, проектными решениями и воркерами такого кэша нет.

Проверка доказанных копий строк КС выполняется один раз для полного набора
позиций каждого `evaluate`, а затем передаётся его компонентам. Это не
отключает проверку: новый вызов с изменёнными данными строит новое доказательство.
Прямой вызов одного компонента по-прежнему проверяет его самостоятельно.

Проверки: `tests/test_monitor_gpr_read_cost.py`, прежние тесты версий и РНВ,
годовой идентичности, доказанных копий и согласованного прогноза Монитора.
Они проверяют копии результатов, границы кэша, различие дат при одинаковых
байтах, отсутствие будущих фактов и сохранность полного финансового builder.
