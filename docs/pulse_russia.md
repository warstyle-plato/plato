# «Пульс продаж»: всероссийский кабинет

Подписка на всю Россию открывает карту на `https://russia.pulsprodaj.ru`
(не на `pulsprodaj.ru`), номер проекта там вида `50-004184` — код региона,
дефис, номер.

## Что поменялось в коде

- **Id проекта — строка** (`pulse_id`). Номер `50-004184` больше не
  приводится к `int` (прежде он ронял весь справочник). Старые числовые id
  дают ту же строку (`4184` → `"4184"`), поэтому сохранённые проекты и
  страницы, открытые до выкатки, находят свои строки без миграции.
- **Код региона** читается только из полного формата `NN-NNNN`; из адреса
  регион выводится лишь как подпись в диагностике, решений по нему нет.
- В тело запроса к API id уходит в том виде, в каком его дала карта:
  голое число — числом, номер с регионом — строкой. Перевода номера в число
  нет: соответствие неизвестно, угадывать его значит спрашивать чужой проект.
- **Кэш по базе**: `DATA_DIR/market/pulse/<хост>/` — справочник, классы,
  куки, карточки. Московский кэш не выдаётся за всероссийский. Прежний общий
  `pulse/projects.json` больше не читается: после выкатки справочник
  собирается заново (первый отчёт или `refresh=1`, см. ниже).
- **Несколько баз**: `PULSE_BASE_URL` принимает список через запятую. Порядок
  — приоритет. Один id из двух баз с точками ближе 1 км — один проект (берётся
  первая база); дальше — конфликт, он считается и показывается в отчёте.
  Цена, остатки и карточка спрашиваются у базы, чей справочник принёс проект.

## Что поставить на проде

На ядре (Яндекс), где живут `PULSE_LOGIN`/`PULSE_PASSWORD`:

    PULSE_BASE_URL=https://russia.pulsprodaj.ru,https://pulsprodaj.ru

Всероссийская база первая, московская запасная — Москва не теряется, даже
если всероссийский кабинет её не покрывает. Логин и пароль — те же
переменные; секреты в этот файл не пишутся. На Render ничего добавлять не надо.

Когда диагностика покажет, что в `russia` есть Москва (`by_id_region` с `77`
или `by_address_region` с «Москва» в сопоставимом количестве, а у второй базы
`duplicates` ≈ всё), вторую базу можно убрать.

## Диагностика (под ключом кабинета)

    GET /market/pulse/catalog                       — только диск
    GET /market/pulse/catalog?refresh=1             — забрать карту и классы заново
    GET /market/pulse/catalog?q=Мытищи&check=1      — подсказка + цена/остатки первого

По каждой базе: `base`, `cache_dir`, `signed_in`, `projects`,
`catalog.updated_at`/`age_hours`/`fresh`, `segments`, `id_format`
(сколько `регион-номер` / `число`), `by_id_region`, `by_address_region`,
`errors`. Сверху — `projects` после слияния, `duplicates`, `conflicts`.

**Критерий приёмки владельцем:** `?refresh=1`, затем `?q=Мытищи&check=1` —
`query.found > 0` и `query.check.ok == true` (есть цена за метр и остаток).

## Что без доступа проверить нельзя (снимет диагностика на проде)

- Та же ли страница входа `/accounts/login/` с CSRF у `russia` — видно по
  `signed_in` и `errors` базы.
- Несёт ли `/map/` у `russia` тот же GeoJSON — `projects > 0`, иначе в
  `errors` «на странице карты нет данных проектов».
- Какой id в GeoJSON — `id_format` и `sample_ids`.
- Отвечают ли `/api/search/` (классы) и `/api/app/complex/*` (цена,
  остатки) — `segments.projects` и `query.check`.
