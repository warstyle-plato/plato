# «Пульс»: стадия, сроки и остатки аналога — со страницы проекта

Сверка владельца по ЗИЛАРТ (Группа ЛСР): у Пульса старт продаж — ноябрь 2015,
срок сдачи «18/IV-27/IV», стадия по корпусам «ввз (сдан/гк) — 18, верхние
этажи — 2». У нас было: старт 01.09.2015, «план. ввод —», «стадия не указана»,
«Остаток 1 416» без единиц. Почти у всех аналогов — то же.

## Почему стадии не было

`project_stage` искал ключ «по смыслу» (`_stage_from_payload`) в точке карты и
таблице проекта (`/api/app/complex/table/`). Стадии там нет. Она живёт на
странице проекта `/complex/<id>/` (и в карточке-балуне на карте)
распределением «стадия → число корпусов».

## Что делает код

- `market_search/pulse_page.py` разбирает видимый текст страницы по подписям
  («Стадия строительства», «Тип договора продажи жилья», «Статус реализации»,
  «Применение эскроу», «Количество жилья», «Квартир», «Начало продаж»,
  «Срок сдачи», «Остатки жилья», «Темп продаж», «по состоянию на» …).
  Возвращает список найденных подписей. Отсутствующая подпись не превращается
  в пустое значение поля.
- `PulseClient.project_page` открывает страницу один раз и кэширует разбор
  на 12 ч. Отказ сети не кэшируется.
- `project_stage` — стадия со страницы по корпусам, с источником
  `pulse_project_page` и датой состояния. Таблица и карта остаются запасными.
- `project_dates` — у каждой даты есть источник, и все кандидаты видны
  (`candidates`). Старшинство источников: страница → таблица API → карта →
  ключи в коде страницы.
- `project_facts` — договор, статус, эскроу и отделка по корпусам; остатки
  со своими единицами (%, шт., м²) и датой; темп продаж в м²/мес.

## Правила (объявлены в коде одним местом)

- **Стадия для цены** — самая ранняя незавершённая стадия корпусов. Страница
  не привязывает стадию к статусу продаж корпуса, а в продаже обычно
  строящиеся корпуса, а не сданные. ЗИЛАРТ: «каркас» (2 корпуса на верхних
  этажах), самая поздняя — «сдан» (18), распределение показывается целиком.
- **Плановый ввод** — последний корпус: «18/IV-27/IV» → IV кв. 2027 (месяц —
  последний в квартале). Первый корпус (IV кв. 2018) показывается рядом.
- **Остаток**: страница «на 1 октября 2026» даёт 10,48 % по штукам квартир,
  балун «на сентябрь 2026» — 55 926 м², 9 %. Это разные базы (шт. и м²) и
  разные даты. Показываются обе цифры с единицами и датами; для «доли» берётся
  более поздняя дата. «Остаток 1 416» из месячной выгрузки подписан теперь
  как «шт · месячная выгрузка».

## Старт продаж: сентябрь против ноября

Без входа в ЛК источник сентября назвать нельзя. Найдены две правдоподобные
причины:

1. Общий разбор дат (`_pulse_date`) не понимал месяцы словами: «Ноябрь 2015»
   в карте, таблице или на странице отбрасывался молча, и побеждал другой
   источник (таблица API или месячная выгрузка). Исправлено.
2. Квартал без месяца («III кв. 2015») разбирается в последний месяц квартала,
   т. е. в 01.09.2015. Для старта продаж это смещение к поздней дате. Не
   менял: сначала нужно увидеть, приходит ли квартал на самом деле.

Ответ даёт маршрут ниже: даты по каждому источнику стоят рядом.

## Диагностика (под ключом кабинета)

    GET /market/pulse/project-page?q=Зиларт
    GET /market/pulse/project-page?complex_id=1695&refresh=1

Что в ответе:

- `page.parsed.labels` — какие подписи разбор узнал на живой странице;
- `stage` — стадия по корпусам;
- `facts` — поля по корпусам;
- `dates.candidates` — даты по каждому источнику;
- `monthly_report` — даты месячной выгрузки.

В «Как посчитана цена» шапка показывает долю аналогов со стадией (с Пульса,
по корпусам, по срокам), с плановым вводом и стартом продаж.

## Что видно только на проде

Образцы `tests/fixtures/pulse/zilart_*.html` собраны по тексту скриншотов
владельца: содержание как в ЛК, вёрстка — реконструкция. Если живая разметка
пишет число корпусов иначе («18» без слова «корпус»), это сразу видно по
`page.parsed.labels` и пустому `stage` в маршруте выше.
