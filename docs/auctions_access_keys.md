# Личные ключи раздела «Торги»

Ключ с областью `auctions` открывает человеку только раздел «Торги» (лоты, КРТ,
карта, выгрузка таблицы) и только для просмотра. Срок действия — 5 дней с выдачи
(`KEY_TTL_SECONDS`, решение владельца); после срока ссылка и cookie не
действуют, нужен новый ключ. Модуль:
`auction_search/access_keys.py`.

## Выдача и отзыв — в боте (только `DEVELOPAID_ADMIN_IDS`)

- `/auction_key Имя` (`/ключ_торгов`): выдать ключ. Бот присылает ссылку
  `…/auctions/enter#k=…`, её нужно переслать человеку. Ключ показывается один
  раз.
- `/auction_keys` (`/ключи_торгов`): список ключей. Для каждого видно, кому
  выдан, когда, действует ли, число входов и время последнего входа (UTC).
- `/auction_revoke номер|Имя` (`/отозвать_ключ`): отозвать ключ. Вход по нему
  перестаёт работать сразу на обоих воркерах.

## Как устроено

- Реестр: `DATA_DIR/market/auction_access_keys.json` на ядре, рядом с
  каталогом КРТ. В реестре хранится sha256 ключа, сам ключ не хранится.
  Запись идёт под `flock`, чтение кэшируется по mtime, потому что воркеров
  два.
- Бот на Render ходит к ядру через `POST /internal/auctions/keys`. Подпись:
  HMAC токеном бота с отметкой времени, запрос действует 5 минут.
- Адрес в ссылке берётся из `AUCTIONS_PUBLIC_URL`. Если переменная не задана,
  берётся база ядра из `MO_CALC_API_URL`/`CORE_API_URL`. Если нет и её —
  адрес мини-приложения.
- Ключ передаётся во фрагменте адреса, и браузер его на сервер не шлёт.
  Страница входа стирает ключ из адресной строки и меняет его на cookie
  `auctions_key`. В cookie лежит номер ключа и HMAC от хеша, а не сам ключ.
- Проверка на сервере: middleware `_auctions_view_gate`, решение даёт
  `access_keys.scope_problem`.
  - Внутри `/auctions` действует тот же белый список только для чтения, что и
    у общего `AUCTIONS_VIEW_KEY`.
  - Вне `/auctions` открыты только запросы карты (`/land/basemap`,
    `/land/map-image`, `/land/lot-context`) и юридические документы подвала.
  - Всё остальное отвечает 403.
- Интерфейс: на странице торгов с таким ключом нет контура и кнопок расчёта,
  передачи в калькулятор и обновления данных (`ui.scoped_page`). Платон по
  торгам есть — см. ниже.
- Пока есть хотя бы один действующий личный ключ, раздел «Торги» без входа
  закрыт, как и при заданном `AUCTIONS_VIEW_KEY`. Остальной сайт для
  посетителей без ключа открыт, как раньше (решение владельца).
- Общий `AUCTIONS_VIEW_KEY` и ключ кабинета продолжают работать как раньше.

## Платон по торгам

Решение владельца: с личным ключом Платон по торгам открыт.

- Вопрос из выдвижной панели идёт в `POST /auctions/ask`, а не в `/cabinet/ask`.
  Адрес задаётся переменной страницы `DEVELOPAID_PLATO_ASK_URL`.
- Кнопка «Рекомендация Платона» в карточке КРТ работает. Уже готовая
  рекомендация отдаётся бесплатно; `refresh` по ключу закрыт.
- Лимит: `AUCTIONS_KEY_PLATO_DAILY` вопросов в сутки (UTC) на ключ, по умолчанию
  20. Счётчик лежит в реестре ключей на диске, он общий для обоих воркеров.
  Сверх лимита — 429 с понятной причиной, модель не спрашивается.
- Рамка темы (`access_keys.PLATO_FRAME`) приклеивается к каждому вопросу:
  отвечать только про торги, лоты и площадки КРТ, расчёт модели не обсуждать.
  Это просьба к модели, а не замок. Замок серверный: общий чат расчёта
  (`/agent/chat`) по ключу закрыт, а Платону доступны только умолчания движка
  и текст вопроса.
- Забор долгого ответа: `GET /agent/result/{id}` и `/agent/trace/{id}` открыты.
