# Частичный ТЭП из документа

Формат `developaid.project.partial-tep`, версия 1, включается только явно.
Обычные `developaid.project.settings` и прежние ProjectPreset не меняют формат.
Файл загружается через «Личный кабинет → Мои проекты → Загрузить файл настроек».
После подтверждения открывается ТЭП с предупреждением и перечнем пробелов;
расчёт автоматически не запускается.

Минимальный синтетический пример:

```json
{
  "kind": "developaid.project.partial-tep",
  "version": 1,
  "name": "Пример неполного документа",
  "source": {"label": "Синтетический документ"},
  "references": {"rnv_quarter": "2028-Q2"},
  "inputs": {"site_area_ha": 0.5, "land_right": "ownership"},
  "tep": {
    "apartments": {"saleable": 2000, "units": 10},
    "underground_parking": {"units": 10}
  },
  "provenance": {
    "tep.apartments.saleable": {
      "origin": "source", "pages": [2], "note": "Прямая площадь"
    }
  }
}
```

В v1 поддержаны квартиры, встроенная коммерция, подземный паркинг и кладовые.
Незаданные поля включённых строк остаются `null`, видны пустыми, не превращаются
в ноль и не заполняются пропорцией. Число мест не задаёт гросс гаража через
норматив 35 м². Площади отдельных квартир/кладовых/мест нельзя выдавать за ГНС
или весь подземный объём. Квартал РНВ хранится справочно: точная дата не выдумывается.

Происхождение `source`, `derived`, `assumption`, `tbd`, страницы и формулы
сохраняются в `inputs._partial_tep.origins` при сохранении проекта, локальном
восстановлении и выгрузке/загрузке настроек. Ручное уточнение помечается
`method=manual`. Это запись происхождения, а не независимая проверка документа.
В `references` можно хранить справочные факты, которые не равны полям модели.
Остальные предустановки подписаны как предпосылки модели, не как данные документа.

До заполнения шести полей каждой строки (ГНС, общая, полезная, продаваемая,
передаваемая, количество), числа гостевых мест паркинга (явный ноль допустим), цены входа, земельных затрат, начала и срока проекта,
применимых цен реализации и СМР недоступны расчёт и финансовые HTML/PDF/Excel.
Ноль допустим только как явно введённое число, не как обозначение неизвестного;
ГНС активного продукта должна быть положительной, срок — целым положительным
числом месяцев. Явно заполненная нулями строка означает отсутствие продукта
(также допускает очередь без этого продукта), а не неизвестные метры.
Сервер проверяет тот же договор независимо от клиентского `ready`/списка пробелов.
Исходные строки получают существующий признак `declared`: нормативные писатели
паркинга, кладовых и соцобъектов не подменяют их геометрию после уточнения.
После заполнения пользователь запускает расчёт отдельно. Никаких новых ставок
или финансовых формул формат не вводит.

Изменение вида проекта на нежилой, добавление отдельного офиса/ТЦ/наземного
паркинга или иных продуктов не входит в этот формат: сервер явно отклоняет
такое сочетание. Для нового полного сценария следует использовать обычный
проект, не удалять маркер неполного источника ради обхода проверки.

Дополнительная защита Excel: даже после уточнения исходников файл не выдаётся,
если существующий сборщик книги сообщил `missing` (нет точного соответствия
полей/формул исходному ТЭП). Пользователь получает явный отказ, исходные данные
остаются в проекте. Обычные проекты сохраняют прежний договор предупреждений
книги; изменение формул Excel в эту задачу не входит.
