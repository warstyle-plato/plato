# Книга нежилого проекта без офиса — каркас v4, один способ продажи

С 24.10.2026 (поручение владельца «Да, следующим PR») нежилой проект без офиса —
ТЦ, ФОК, наземный паркинг, в том числе с объектами по ДДУ, — получает ту же
книгу, что проект с офисом: `office_workbook` на каркасе жилой v4
(`docs/office_workbook.md`). Прежняя книга (`nonres_workbook`: листы «Затраты»,
«Объект N», «ДДУ N», «Кредит», «Денежный поток», «Сверка», время вниз по
строкам) убрана.

Маршрут: `xlsx_book_v4_build._nonres_project_workbook` → `office_workbook.build`.
Офис в проекте есть — книга считает три способа продажи офиса
(`office_paths`); офиса нет — `office_keys` пуст, и книга считает один способ
(`PROJECT_PATH`, «Стратегия объектов проекта»). Исключение прежнее: проект с
очередями и ПФ получает книгу v4.

## Один способ — стратегия объекта

Сравнения путей, как у офиса, нет. Каждый объект продаётся стратегией, выбранной
у него на странице проекта:

| Стратегия объекта | Лист объекта | Повторяет в движке |
|---|---|---|
| Продажа по ДДУ (эскроу и ПФ) | продажи по ДДУ: доля до ввода и остаток, рост цены, профиль и лестница цены, маркетинг, налоговая маржа; ПФ — на листе «ПФ» | `sales_schedule`, `simulate_financing`, НДС и LLCR `_financing_totals` |
| Продажа блоками после ввода | продажа, свой кредит, итоги объекта | `object_flows` (`direct`) |
| Аренда и продажа здания | аренда, NOI, выход, свой кредит, итоги объекта | `object_flows` (`income`) |

## Листы

Дашборд, ОТЧЕТ, Вводные, ИНСТРУКЦИЯ, ТЭП, СРОКИ, CAPEX, Ставки, листы объектов
(«Коммерция ОСЗ», «ФОК - медцентр», «Наземный паркинг»…), ПФ (только если есть
объект по ДДУ), CF, Налоги, ПРОВЕРКИ. Листов трёх способов офиса («Продажа ДДУ»,
«Продажа», «Аренда», «Выход», «CF_ДДУ»…), шкалы класса офиса и «Источников» нет.
Вид — как у жилой v4 и книги офиса; ярлык листа объекта — цветом его стратегии.

Excel не допускает в имени листа `[]:*?/\`: «ФОК / медцентр» — лист
«ФОК - медцентр».

## ОТЧЕТ и Дашборд

- ОТЧЕТ — один столбец «Стратегия объектов проекта»; строка «Способ, выбранный в
  проекте» перечисляет объекты и их стратегии. Раздела «Офис» и строки
  «Выгоднее по NPV» нет.
- Дашборд — NPV и IRR проекта и собственника, чистая прибыль, пик своих денег,
  выручка, LLCR и пик эскроу (есть объект по ДДУ) или DSCR и пик долга объектов,
  вердикт «ПРОВЕРОК».

## ПРОВЕРКИ

Книга сверяется с основным расчётом движка подробно, как способ проекта у офиса:
проект, смета, ПФ и продажи по ДДУ, объекты на своём кредите, собственное участие,
по годам, горизонт. Вердикт не «ПРОЙДЕНО» — в `missing` выгрузки с названием
расхождения.

## Проверка

- `tests/test_nonres_workbook.py` — двенадцать проектов сходятся с движком: ТЦ
  блоками, ТЦ в аренде (продажа, удержание, баллон), ТЦ по ДДУ (с процентами
  БРИДЖа капиталом, своими деньгами, лимитом, профилем и лестницей цены), ФОК по
  ДДУ, наземный паркинг по ДДУ, ФОК и паркинг по ДДУ, паркинг по ДДУ рядом с ТЦ
  в аренде, ТЦ блоками рядом с ФОК по ДДУ. Подделка формулы аренды, статьи
  сметы, вводной, даты ставки, правила налога, выхода, срока, ставки ПФ и цены
  по ДДУ ТЦ, ФОК и паркинга краснит «ПРОВЕРКИ». Тест краснеет, если нежилой
  проект без офиса уйдёт в другую книгу.
- `scripts/excel_book_parity.py --only nonres_sports_ddu nonres_parking_ddu` —
  те же сценарии ФОК и паркинга через LibreOffice; тест читает значения
  `xlsx_eval` тем же `report()`.

## Известное расхождение (не книги)

ФОК, переданный городу, рядом с ТЦ в аренде: движок кладёт стройку ФОК в
проектное финансирование, хотя продаж по ДДУ в проекте нет, и ПФ к концу не
гасится («N/A — долг не погашен»). Книга этого не повторяет, и «ПРОВЕРКИ»
показывают расхождение в процентах, налоге и NPV. Так было и в прежней книге.
Вопрос методики движка — в `docs/questions_backlog.md`.
