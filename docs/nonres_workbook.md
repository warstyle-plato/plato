# Книга нежилого проекта — финансовая модель формулами

Книгу отдаёт `main_legacy.build_project_workbook`, когда у нежилого проекта нет
ДДУ (`report.layout.project_finance = False`). Собирает `nonres_workbook.build`
из двух вещей: авторитетного расчёта (`consolidated`) — он нужен только листу
«Сверка» — и вводных (`main_legacy.nonres_book_spec`), которые движок читал.

## Откуда вводные

`prepared_calculation(x, t, rates)` — одна подготовка вводных, ТЭП и кривой
ставки на расчёт и на книгу: правки ТЭП (паркинг, соцобъекты, нежилой тип,
экземпляры объектов) идут одним порядком. `nonres_book_spec` берёт каждое число
тем же вызовом `n(x, ключ, умолчание)`, что `build_operating_model` и
`object_flows`; разойдись умолчание — покраснеет «Сверка».

## Листы

| Лист | Что считает | Повторяет в движке |
|---|---|---|
| Вводные | только значения; списки по-русски, даты датами | — |
| Затраты | смета «ставка × база», график: S-кривая, равномерно, разово, профиль управления, график оплаты участка; общие затраты на кредит объектов | `build_operating_model` |
| Объект N | выручка, эксплуатация, НДС, кредит, налоговая маржа; итог объекта как отдельного проекта | `object_flows`, `object_financing`, `object_result` |
| Кредит | ключевая ставка по сценарию, сумма по объектам (плата за резервирование лимита НКЛ — на листе объекта) | `rate_lookup`, `object_flows` |
| Налоги | НДС, налог на прибыль: общие затраты признаются в РВЭ, перенос убытка с ограничением доли базы года | `_profit_tax_schedule` |
| Денежный поток | поток проекта (NPV) и собственника (IRR), раскладка вложений и возврата | `_calculate_economics`, `equity_participation_report` |
| Отчёт | экономика, «как сложены итоги» (выручка − расходы всего = чистая прибыль; EBITDA − проценты = прибыль до налога), структура расходов, финансирование объектов, собственное участие, ОПУ по годам, по годам — ссылками | `summary`, `report` |
| Сверка | каждый итог против движка; «ПРОЙДЕНО» / «РАСХОЖДЕНИЯ»; список missing | — |

Все помесячные таблицы начинаются со строки `FIRST_ROW` (месяц k = 0 — старт
проекта), у объекта — ещё год после горизонта: NOI покупателя для выхода.

## Читаемость

Коды движка (`direct`, `sweep`, `flat`…) в книгу не попадают: выбор — списками
по-русски. На листе объекта блок другой стратегии свёрнут группой столбцов.
Рост цены до ввода подписан годовым эквивалентом и источником: умолчание
объекта — `StandaloneObject.growth_pre_default` реестра (офисы и ТЦ 1,5 %/мес.),
у жилья своё — `monthly_growth_pre_pct` (1 %/мес.).

Чувствительности таблицами данных Excel книга не строит: вычислитель их не
считает, а непроверенная формула в книгу не идёт. Сценарии — множители выручки
и затрат на «Вводных».

## Чего формулой нет (missing)

Благоустройство (методика двора), соцобъекты и рассрочка ВРИ приходят
значениями движка, подписаны «СЧИТАЕТ ДВИЖОК» и перечислены в `meta["missing"]`
и на «Сверке». У нежилого проекта они обычно нулевые.

## Две тонкости, о которые спотыкается Excel

- Баллон аннуитета берётся из долга стройки до погашений (`bal_build`), а не
  из долга месяца ввода: строки после ввода сами читают баллон, и ссылка на
  долг месяца ввода через сумму столбца — цикл для Excel.
- Число строк таблиц задаёт горизонт движка. Правка вводных, уводящая проект
  дальше, краснит строку «Горизонт модели» на «Сверке», а не обрезает поток.

Проверка: `tests/test_nonres_workbook.py` — пять проектов сходятся с движком
по всем строкам «Сверки» (вычислитель `xlsx_eval`), подделки формулы, статьи
сметы, вводной, правила налога и горизонта её краснят.
