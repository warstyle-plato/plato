# Реестр российского ПО: что мешает и порядок работ

Цель владельца: платформа должна соответствовать требованиям для включения в единый
реестр российских программ (Минцифры, ПП РФ № 1236 от 16.11.2015 с изменениями).

Этот документ — рамка работ, а не юридическое заключение. Требования пересказаны по
вторичным источникам (ссылки внизу); перед подачей заявки формулировки и сроки
сверяет юрист по действующей редакции ПП № 1236 на Гаранте/Консультанте и по
разъяснениям Минцифры.

## Что проверяет реестр

Условия правообладателя и продукта (юридические, кодом не решаются):

- исключительное право на программу принадлежит российскому юрлицу (иностранное
  участие менее 50 %) или гражданину РФ — на всей территории мира и бессрочно;
- программа законно введена в оборот в РФ и свободно продаётся на всей территории РФ;
- выплаты иностранным лицам по договорам, связанным с программой (лицензии, агенты,
  сервисы), — менее 30 % выручки от программы;
- нет принудительного обновления и управления из-за рубежа;
- сведения о программе не составляют государственную тайну.

Требование совместимости (вводится поэтапно с 2026 года, сроки для класса программы
проверить по тексту постановления): программа работает как минимум с двумя
российскими операционными системами, которые есть в реестре и признаны доверенными
(например, Astra Linux и РЕД ОС). По источникам, жёсткое требование «двух ОС»
относится прежде всего к настольным программам; для прикладного ПО сроки — 2027–2028.

Пакет документов к заявке: описание функциональных характеристик, руководство по
установке, руководство пользователя, описание процессов жизненного цикла (разработка,
поддержка, кто её ведёт), стоимость, демонстрационный доступ для экспертов, класс ПО
по классификатору Минцифры, документы о правах на код.

## Windows для реестра не нужен

Реестр не требует Windows-версии. Наоборот, совместимость подтверждается с
российскими ОС на базе Linux. Сервер платформы уже работает на Linux (`Dockerfile`,
`python:3.11-slim`), поэтому ближайшая цель — подтвердить работу серверной части на
Astra Linux и РЕД ОС и работу страницы в браузерах, которые на них стоят (Яндекс
Браузер, Chromium). Отдельное приложение для Windows — по желанию, к реестру не
относится.

Проверено и не мешает: остальные библиотеки (`fastapi`, `uvicorn`, `pydantic`,
`reportlab`, `openpyxl`, `pypdf`, `python-pptx`, `Pillow`, `segno`, `playwright`) —
свободные разрешительные лицензии; `pyxlsb` — LGPL-3.0, допустима при обычном
импорте без изменения библиотеки. Оплата — ЮKassa, аналитика — Яндекс Метрика,
НСПД и торги — российские источники. Шрифты Google встречаются только в макете
`docs/experiments/`, на рабочие страницы не попадают.

## Не код, но обязательно

- **Права на код.** Большая часть изменений сделана с помощью ИИ-ассистента (строки
  `Co-Authored-By` в коммитах). Юристу — оформить цепочку прав на правообладателя:
  кто автор по ГК РФ, служебные задания или договоры отчуждения с людьми, которые
  ставили задачи и принимали код; условия использования ассистента о правах на
  результат.
- **Продажа в РФ.** Оферта или лицензионный договор, прайс, поддержка российским
  юрлицом.
- **Доля иностранных выплат.** Посчитать долю расходов, связанных с программой, в
  пользу иностранных лиц (модель, хостинг, подписки) — после пунктов 1, 2 и 5 она
  должна стать заметно меньше 30 % выручки.
- **Документы для экспертизы.** Пакет из раздела «Что проверяет реестр» и
  демонстрационный стенд в РФ.

## Порядок работ (отдельными PR)

1. Российский поставщик модели для Платона, иностранные — только по настройке (п. 1).
2. Замена PyMuPDF (п. 4) — с проверкой на тех же PDF, что сейчас разбираются.
3. Свой вход и привязка платного доступа к нему, Telegram — второй канал (п. 3).
4. Перенос бота и мини-приложения с Render на ядро; удаление `render_proxy` (п. 2).
5. Подложка и геокодер по умолчанию российские (п. 6).
6. Хранилище и сборка в РФ (п. 5) — решение владельца о площадке.
7. Стенд на Astra Linux и РЕД ОС, подтверждения совместимости (п. 7).
8. Пакет документов и заявка — параллельно с юристом.
