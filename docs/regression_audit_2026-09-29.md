# Аудит регрессов: выпуски 0.24.56 → 0.24.84 (28–29.09.2026)

Вопрос владельца: «сколько такого регресса случилось ещё в разных аспектах?» после
трёх жалоб 29.09 (паркинг первых этажей офиса не уменьшает продаваемую ОСЗ; таблица
ТЭП на телефоне без подписей; LLCR проекта «сам» 1,20 → 1,24). Эти три случая ведёт
сессия `session_01KyXiE1w4hPvnJ3PtBvrWES`; здесь они только перечислены вместе с тем,
что показал замер.

Ответ замером: **в серверной экономике за окно регрессов (в) нет** — каждое
изменение числа между соседними выпусками объясняется своим PR. Побочных эффектов
(б) — четыре, два из них уже закрыты следующими PR. Кроме того, найдены **два
долгоживущих дефекта страницы** (появились до окна, 05.08 и 07.09), которые дают
ровно те симптомы, на которые жалуется владелец: LLCR «сам» растёт после
перезагрузки страницы, и продаваемая офиса в ТЭП уменьшается с каждой правкой
любого поля.

Жалобы владельца, которые ведёт `session_01KyXiE1w4hPvnJ3PtBvrWES`, — что показал
этот замер:

- **Паркинг первых этажей и продаваемая ОСЗ.** Движок вычитает на всех 32
  выпусках одинаково (офис 24 000 → 23 400 м², выручка 13 283 → 12 951 млн при 40
  местах). Регресса окна нет; есть дефект №2 (с каждой правкой вычитается ещё раз) и
  расхождение ТЭП с деньгами. Если в строке ТЭП офиса пусто (объект заведён только
  формой ОСЗ, без строки ТЭП), движок отдаёт продаваемую строки 0 при верной выручке.
- **Подписи таблицы ТЭП на телефоне.** На классической странице (вкладка ТЭП и
  таблицы отчёта) на 390 px подписи, заголовки и ширины колонок совпадают на 0.24.56
  и 0.24.84 (ширина колонки «Продукт» 137 px, таблица 894 px с горизонтальной
  прокруткой внутри блока 312 px). Здесь не воспроизведено — вероятно, другая
  поверхность (IA, мини-приложение, дашборд). Не проверялось.
- **LLCR 1,20 → 1,24 «сам».** Ни один выпуск окна не поднимает LLCR проекта с
  сохранённым состоянием: на странице 1,1206 на всех 32 выпусках. Единственное
  изменение LLCR по умолчанию (#581, рост цены 1,5 → 1 %/мес.) его **снижает** и
  не трогает сохранённые проекты (значение 1,5 лежит в их состоянии). Рост без
  действий человека даёт дефект №1: +0,029…+0,030 после перезагрузки страницы.

## Как мерили

- `scripts/golden_snapshot.py --root <worktree> --out snap.json` на git worktree
  каждого коммита слияния с 0.24.56 (ab5279f) по 0.24.84 (63f3958), 32 коммита;
  8 эталонов: по умолчанию, Нагатино очередями (пресет), жильё + ОСЗ-офис с гаражом
  200 + 40 мест на 1 этажах, ТЦ + ФОК, нежилой, экземпляры в двух очередях, КРТ из
  каталога (Варшавское ш., вл. 37, рынок зафиксирован), состояние 0.24.56 поверх
  умолчаний. Снимались ТЭП по строкам, выручка по продуктам, CAPEX по статьям,
  финансирование, LLCR, NPV, IRR капитала (IRR проекта и DSCR движок не считает —
  их и нет в снимке), итоги и строки отчёта, по очередям — итоги и ТЭП.
- Страница — настоящий `PAGE` каждого выпуска в Chromium, 390 и 1300 px: поля
  заполнялись событиями, как у человека, пересчёт — кнопочным `calculate()`;
  измерялись ТЭП в `tep`, итоги `lastResult`, подписи/колонки/обрезка первой колонки
  всех видимых таблиц вкладок ТЭП, Отчёт, Вводные. Дефекты №1 и №2 воспроизводятся
  детерминированно: №1 — «открыть → пересчитать → перезагрузить», №2 — «ввести 40
  мест на 1 этажах → трижды поправить цену квартир».
- Сравнение соседних выпусков с допуском 1e-6 относительной величины; каждое
  изменение сверено с текстом PR.

Не проверялись: Telegram-бот и мини-приложение, IA-слой, тизер, дашборд v4 вне
книги, проекты, сохранённые на сервере (`_PROJECTS_DIR`), Нагатино на странице.

## Сторож (этап 2)

`tests/test_golden_numbers_do_not_move_silently.py` + `tests/golden/`: ключевые
числа тех же 8 эталонов; тест падает на любом их изменении. Обновление — только
`python3 scripts/golden_snapshot.py --update --reason "…"` отдельным коммитом
(скрипт пишет строку в `tests/golden/CHANGES.md`, тест сверяет отпечаток снимков с
ней) и строкой `Эталоны: …` в описании PR. Подробно — `tests/golden/README.md`.

Сторож держит движок. Дефекты №1 и №2 живут на странице, и числа движка они не
меняют — их проверки должны появиться вместе с исправлением (браузерный прогон
«перезагрузка не меняет LLCR», «пересчёт не меняет ТЭП»).
