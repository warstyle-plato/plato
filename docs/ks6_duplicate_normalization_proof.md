# Ограниченное доказательство копий КС-6а

`POST /monitor/contracts/source-duplicate-proof` доступен только с действующим
административным ключом, через прежние фоновые задания и ticket/result Монитора.
Запрос закрытый: project, cut, ровно один book_sha256 и ранее полученный
corpus_token; обычные key/session/ticket остаются транспортными полями.
Пути, строки, формулы, диапазоны и произвольные ячейки клиент не выбирает.

Проекция `ks6-native-duplicate-proof-v1` перечитывает неизменяемые оригиналы,
проверяет прежний корпус до и после чтения и декодирует выбранную книгу текущим
нативным парсером. Возвращаются только:

- собственные SID/даты архивов, SHA книги и хеши исходных имён;
- CURRENT producer schema/code pins, без утверждения о схеме сохранённого импорта;
- хеши полного упорядоченного native item universe и прежнего audit-view items
  каждого физического record; порядки относятся к текущему разбору книги;
- для помеченных пар копия→оригинал: локаторы, native/audit input digests,
  результат `_sum_row_range` (нулевой индекс колонки и включительные номера
  строк) либо invalid/null, а также неизменённый native verdict
  `verified_duplicate_sources`;
- общий projection_sha256: SHA-256 канонического JSON всего ответа без этого
  поля (UTF-8, ensure_ascii=False, sort_keys=True, separators=(',', ':'),
  allow_nan=False). Он связывает input pins, порядок, locators, producer и
  project/cut/book/corpus. Одного совпадения номеров строк недостаточно.

Формулы, исходные ячейки, количества, позиции и денежные суммы не выдаются.
Сами native/audit inputs также не возвращаются. Audit pins используют ровно
`source-audit-page-v1` items, включая относительные координаты и признаки среза.
Семантика исключения копий не меняется: флаг сам по себе не подтверждает копию.
Неверное основание остаётся с verdict=false и нормализацией invalid/null.

Пределы: одна книга, 8 листов/физических записей, 4096 позиций, 16384 периодов,
8 оснований, 16 proof-ячеек всего, 100000 материализованных ячеек, 64 КиБ ответа.
Общий корпус остаётся под прежними пределами 32 архивов и 64 МиБ оригиналов.
Превышение или изменение источников/пространства/кода прекращает весь ответ;
частичный результат не признаётся доказательством.

Это RAW seam, без header corrections, identity journal, persisted source-index,
документов, сроков и связей. Полнота такого ответа не означает полноту корпуса,
операционную привязку, финансовую приёмку или право выполнять реальную фазу.
Для будущего offline oracle нужны отдельная проверка точного HEAD, совпадение
всех контекстных и audit input pins и проверка exclusion map без изменения
остальной native duplicate semantics. Сам endpoint такой oracle не добавляет.
