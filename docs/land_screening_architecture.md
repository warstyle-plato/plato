# Градостроительный скрининг участка — архитектура (владелец, 16.08.2026)

Цель: не заменить архитектора и не доказать, что ТЭП садится, а автоматически
собрать максимум объективных ограничений по кадастру/координате и показать
инвестору ранние red flags до глубокой градпроработки.

Источники делятся на два класса:
1. Runtime-источники — опрашиваются автоматически при каждом расчёте.
2. Нормативная локальная база — поддерживается нами из официальных документов.

Конвейер: кадастр/координата → ЕГРН/НСПД → ЗОУИТ → ПЗЗ/территориальная зона →
красные линии/ППТ (если доступны) → окружающая застройка → рельеф →
нормативы РНГП → отдельные checks → итоговый screening.

## 1. НСПД
Работает: `https://nspd.gov.ru/api/aeggis/v3/{layer_id}/wms`, слой 36048
(ЗУ ЕГРН), GetMap и GetFeatureInfo, EPSG:3857, браузерные заголовки против WAF.
Существующую интеграцию не менять.

ЗОУИТ: кандидаты внутренних слоёв **37577–37581 — НЕ подтверждены**. Не
hardcode до runtime-проверки из нашей инфраструктуры: Росреестр не публикует
их как официальный API-контракт (урок «22,5/25/35»: правдоподобное число —
ещё не то число).

Слой конфигурации: `layer_id, logical_name, api_version,
expected_feature_type, last_verified_at, active` + health-check/canary.
Слой перестал отвечать → конкретная проверка UNAVAILABLE, расчёт не падает.
Запрещён вывод «ЗОУИТ отсутствует» из пустого ответа; правильный текст —
«В НСПД ограничение не обнаружено».

## 2. ПЗЗ Москвы
Подтверждённого открытого production-API (координата → подзона + плотность +
высота + % застройки + «Ф») нет — UNRESOLVED.

Кандидат на проверку (найден владельцем, 16.08.2026):
`https://gisogd.mos.ru` — ГИСОГД Москвы. Из песочницы сессии не достать
(egress-прокси); владелец прислал скриншоты (17.08.2026): живая
интерактивная «Карта градостроительства» с деревом слоёв плюс перечень
разделов `/chapters`. **Опознавать разделы по названиям, не по номерам:**
дерево слоёв карты и `/chapters` нумеруют их по-разному (в дереве
зонирование шло третьим, в перечне — пятым). По скриншоту `/chapters`
(официальная нумерация ГИСОГД):

- раздел 4 — **Нормативы градостроительного проектирования** — РНГП Москвы
  документами; источник для локальной rule-base по Москве (сейчас раздел 7
  этого документа покрывает только МО);
- раздел 5 — **Градостроительное зонирование** — это ПЗЗ (подзоны, наш раздел 2);
- раздел 7 — **Планировка территории города Москвы** — ППТ, то есть
  красные линии (наш раздел 4);
- в дереве слоёв карты видны также **ЗОУИТ** (второй источник рядом с НСПД)
  и **План наземных и подземных коммуникаций** — того, что больше нигде в
  открытом доступе нет; их номера в `/chapters` на скриншот не попали —
  сверить пробой.

Раз слои рисуются на интерактивной карте — браузер дёргает тайловый или
WMS/feature-сервис, и его адреса лежат в конфиге страницы или видны в
network-запросах. Проба С ЯДРА: забрать страницу карты и её JS, вытащить
URL сервисов (в духе `curl -sS "https://gisogd.mos.ru/..." -A "Mozilla/5.0"
| grep -oE '"https?://[^"]*(api|arcgis|wms|tile)[^"]*"'`), затем живой
GetMap/identify по знакомому участку — тот же метод, что `/land/map-probe`.
Статус ПЗЗ Москвы после скриншотов: **кандидат с высокой вероятностью**,
но правило прежнее — кандидат не контракт, пока не подтверждён живым
ответом с ядра. Не тратить время на старые data.mos-датасеты и reverse
engineering случайных endpoint. Архитектурно — интерфейс `PZZProvider`,
реализация отдельным адаптером; перспектива — собственная PostGIS-база
подзон, обновляемая по официальным изменениям ПЗЗ (ПП № 120-ПП и далее).

## 3. ПЗЗ Московской области
Аналогично: РГИС МО показывает ПЗЗ визуально, договорного публичного API нет.
source = local normalized PZZ database, не runtime-scraping РГИС.

## 4. Красные линии
Hard-check не делать: стабильный слой не подтверждён, полнота внесения в ЕГРН
неизвестна, часть линий живёт в ППТ. Возможен только флаг RED_LINE_DETECTED;
отсутствие найденной линии НЕ означает отсутствия красных линий.
Кандидат-источник — раздел «Планировка территории города Москвы» ГИСОГД
(в `/chapters` — номер 7), проверяется той же пробой с ядра, что и ПЗЗ
(см. раздел 2).

## 5. Окружающая застройка
НСПД ОКС (этажность, если заполнена) + Overture Buildings, fallback —
OSM building:levels/height. Это не норматив — только информационный контекст.

## 6. Рельеф
Copernicus DEM GLO-30 как coarse screening. FABDEM в production не брать
(NC-лицензия). Вывод: «уклон участка ориентировочно X% — предварительная
оценка по DEM ~30 м, не вертикальная планировка».

## 7. Нормативы МО
Локальная rule-base по действующей редакции ПП МО № 713/30 + изменения,
включая № 774-ПП от 02.07.2026. Нормативы в runtime через LLM не искать.
Поля правила: `rule_id, territory, value, unit, rule_type, scope, area_basis,
conditions, effective_from, document, point_table, quote, official_source`.
Hard FAIL могут давать только MANDATORY_MINIMUM / MANDATORY_MAXIMUM;
RECOMMENDED — информационный warning.

## 8. Результат
Не один магический статус, а независимые чеки:
ЕГРН OK · ЗОУИТ WARNING · ПЗЗ UNAVAILABLE/OK/FAIL · парковки OK/FAIL ·
мин. территория РНГП OK/FAIL · красные линии DETECTED/NOT_DETECTED ·
рельеф INFO · окружающая этажность INFO.
Итог: CRITICAL / WARNING / NO_CRITICAL_FLAGS.
Запрещено «проект точно помещается»; максимум — «по автоматически
проверяемым ограничениям критических несоответствий не выявлено».

## 9. MVP (гипотеза владельца, подтверждена аудитом 16.08.2026)
1) кадастр + площадь (есть целиком); 2) ЗОУИТ НСПД (нужна проба слоёв);
3) парковки МО (движок уже считает — нужен только статус);
4) мин. территория РНГП МО (баланс уже считается — нужен только статус);
5) coarse slope (новый малый модуль); 6) ИЖС-окружение (готово) +
этажность ОКС (после пробы). Физика посадки (СПП → этажность/высота на
пятне) — INFO без внешних источников. ПЗЗ и красные линии — когда будет
надёжный источник. Пересечение геометрий в MVP — сеткой точек через готовый
GetFeatureInfo (без новых зависимостей); shapely/PostGIS — вместе со своей
базой ПЗЗ.

Места в интерфейсе: блок в «Участке» под карточкой участка; в отчёте раздел
«Реализуемость посадки» ПЕРЕД «Оценкой целесообразности покупки»; главный
флаг — в карточку решения.
