# ОКС и ЗУ в контуре КРТ: снос и выкуп

Задача владельца (29.09.2026): для любой площадки КРТ найти ОКС и ЗУ по контуру
КРТ и считать по ним снос и выкуп в расчёте проекта.

## Кто за что отвечает

| Вопрос | Владелец |
|---|---|
| Контур площадки | `_krt_site_finder` (файл карты реестра → участки перечня решения) |
| Запрос к НСПД рамкой | движок: `_nspd_layer_in_bounds` → `_nspd_getfeatureinfo(bounds=…)`; с Render — `POST /land/contour-objects` на ядро |
| Сетка рамок, дробление, доля в контуре | `auction_search/krt_contour_objects.collect` (доля — `nagatino_parcels.share_inside`) |
| Сверка с перечнем | `krt_contour_objects.reconcile` |
| Площадь сноса | `krt_contour_objects.demolition` → вводная `demolition_area_sqm` + `_demolition_source` |
| Собственник и выкуп | `krt_investment_score._cached_cadastral_buyout` (кэш ЕГРН по номеру, «Москва / не Москва / не определён») |
| Список номеров выкупа | `krt_contour_objects.buyout_numbers` — один на карточку и на денежную нагрузку |

## Правила

- Слои: 36048 ЗУ, 36049 здания, 36328 сооружения, 36329 ОНС. Роль объекта — по
  слою, который спрашивали; расхождение с видом из ответа называется
  (`kind_conflict`).
- Рамка отвечает не больше 50 объектов; упёрлась — делится на четыре, до трёх
  уровней; дальше ответ помечается неполным (`truncated`).
- «В контуре» — не меньше 50 % пятна внутри; меньше — «на границе», в расчёт
  не идёт, называется списком. Без пятна — «доля не измерена».
- Снос: судьба из решения (снос → считается, площадь решения, иначе ЕГРН;
  снос/реконструкция → не считается, названо; реконструкция/сохранение → нет).
  Судьба не названа → здание в контуре считается под снос, это допущение
  называется. Сооружения и ОНС в площадь не идут. Здание перечня со сносом,
  не найденное на карте, считается по решению.
- Ручная площадь сноса не затирается: ручная — ненулевая без отметки или с
  отметкой другого числа.
- Выкуп: не-московские — кадастровая стоимость с подписью «не цена сделки»;
  Москва — 0 с причиной; «не определён» — не 0, итог не закрыт, номера
  перечислены.

## Выкуп — своя статья CAPEX (решение владельца, 29.09.2026)

- Вводная `land_buyout_mln` «Выкуп ЗУ/ОКС у третьих лиц», млн ₽. Статья
  `land_buyout` движка платится равными долями в окне до РнС (то же окно, что
  у сноса и расселения), в очередях делится долей подготовки, в резерв не
  входит (приобретение, а не работы), в лимит БРИДЖа — как снос: не входит.
- Книга v4: строка 39 блока CAPEX каждой очереди, в итоге блока, вне базы
  резерва; ячейка «Вводных» F42. Служебная строка «база лимита БРИДЖа» из
  строки 39 убрана — та же база считается в формуле CF (SUMIF по месяцам до
  РнС). Книга M2: статья «Выкуп ЗУ/ОКС у третьих лиц», вне базы резерва.
- Отчёт и PDF: строка структуры расходов с удельными на наземную ГНС и
  продаваемую площадь.
- КРТ: модель площадки подставляет оценку выкупа по контуру с отметкой
  `_land_buyout_source` («кадастровая стоимость, не цена сделки»); ручное
  значение не затирается; «собственник не определён» — предупреждение с
  перечнем, в число входят только доказанные. Цена входа выкупом больше не
  нагружается: денежная нагрузка ставит ту же статью, ёмкость входа — цена
  права КРТ без вычета.
- Проекты не из КРТ: вводная пуста, статья ноль; эталоны сдвинулись только
  новыми нулевыми ключами (`capex.land_buyout`, доли очередей).

## Что мерить на ядре

1. `GET /land/screen-probe?layers=36049,36328,36329&lat=…&lng=…` в точке с
   известным зданием — слой отвечает, `categoryName` совпадает с ролью.
2. `POST /land/contour-objects` с контуром одной площадки (кольца из
   `/auctions/krt/<slug>/point` → `rings_merc`) — число запросов, отказы,
   `truncated`; сохранить ответ как живой образец в `tests/fixtures`.
3. Порядок осей BBOX (WMS 1.3.0, EPSG:4326) — тот же, что у скрининга по
   контуру; если здания не приходят при живом слое — первым проверить его.
