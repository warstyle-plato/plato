# Вопросы Платона в чат отдела продаж

Владелец (02.11.2026): «А Платон из бота может такие брони мониторить и
сравнивать с этим файлом, чтобы задавать вопросы?» — «пусть пишет в чат, но
коротко и извиняюсь».

- Вопросы собирает ядро (`market_search/sales_questions.py`) на каждый НОВЫЙ
  ежедневный отчёт чата (повтор доставки Telegram вопросов не повторяет); бот
  отправляет их одним сообщением в тот же чат: «Извините, это Платон Сергеевич
  Федоскин, у меня возник вопрос…», не больше трёх за раз.
- О чём: договор подписан больше недели назад, а на эскроу меньше 5% суммы
  (сначала крупные суммы); бронь ушла из «Текущих броней» за последние две
  недели, а договора на эту квартиру в выгрузке нет (`booking_outcomes`, исход
  «снята без сделки»); вариант оплаты, который правило отчёта о продажах не
  узнаёт; цена метра ниже медианы договоров той же комнатности больше чем на 15%
  за три месяца (прайса в источниках нет — сравнение со сделками,
  и вопрос так и говорит).
- Вопросы о деньгах и бронях — только при свежей выгрузке договоров (не старше
  недели от отчёта): по старой выгрузке «денег нет» значит «мы их не видим».
- Вопрос не повторяется никогда (владелец: «и нельзя повторять вопросы»). Ключ —
  договор или квартира и день ухода брони, а не текст: пришёл частичный платёж,
  уточнили площадь, загрузили новую выгрузку — вопрос тот же. Заданные лежат
  отдельным файлом `cabinet/<проект>.asked.json`, а не в источнике: новая
  выгрузка чата или договоров их не стирает. Сбор и запись — под блокировкой
  файла (два воркера). Запись — до отправки: сбой отправки теряет вопрос, а не
  повторяет. Файл не читается — вопросов нет, причина видна в /status.
- Строительные чаты не затронуты: там бот по-прежнему молчит.

Проверка — `tests/test_platon_asks_the_sales_chat.py` (синтетика). Сводка руководству — `docs/management_report.md`.

Уточнение владельца 04.11.2026: ценовой вопрос нужен только об удешевлении.
Продажа выше базы и снижение ровно на 15% не вызывают вопрос о цене.
Это не отменяет вопросы о неоплате, пропавшей брони или непонятной схеме оплаты.

## Ответы менеджеров

Ответ принимается через «Ответить» (Reply) на сообщение Платона. Проверяется
Telegram ID отправителя исходного вопроса: другой бот или человек с тем же
именем не подходят. Обычные сообщения группы не считаются ответами по догадке.
Бот сохраняет ответ молча; результат или ошибка видны в `/status`.

Журнал `cabinet/dialogues/<проект>.json` хранится на ядре под той же файловой
блокировкой, что и `.asked.json`: исходные вопросы с их ключами, ID чата и
сообщения, текст ответа, автора, Telegram ID автора и время Telegram.
Подтверждение отправки связывает вопрос с выданным Telegram message_id;
если оно потерялось, Reply сопоставляется по полному тексту исходного вопроса.
Повторная доставка одного ответа не создаёт копию. Новая выгрузка источников
не стирает журнал; его ключи также исключают повторные вопросы. Повреждённый
журнал останавливает вопросы, а не запускает их по второму кругу.
Создание вопросов, подтверждение отправки и разрешение исходного проекта
ответа также выполняются под общей блокировкой происхождения, перед
блокировкой проекта: два воркера не выбирают разные проекты в гонке.

Ответ привязывается к сообщению с вопросами. Если менеджер ответил только на
один из трёх пунктов, остальные не помечаются закрытыми. Пояснения и обещания
хранятся дословно; дата в ответе не становится подтверждённым графиком платежей.
Эскроу и контрактация продолжают читаться из своих источников, а не из слов
менеджера. Автоматический повторный опрос по обещанному сроку не введён.

При перепривязке чата Reply остаётся в исходном проекте: он определяется по
сохранённому ID сообщения/чата, а при потерянном подтверждении отправки —
по уникальному полному тексту ещё не подтверждённой отправки.
Reply на старое сообщение Платона тоже сохраняется с процитированным вопросом,
но без выдуманной связи со всеми ключами старого `.asked.json` и без
приписывания текущему проекту. Такие ответы лежат отдельно по чату:
`unattributed/cabinet/dialogues/<chat_id>.json`; `/status` показывает отсутствие
надёжной связи с проектом. Telegram Bot API
не даёт боту загрузить историю группы: ответы, пропущенные до исправления,
нужно передать снова через Reply на исходное сообщение после выпуска.

Проверки: `tests/test_sales_chat_answers.py`, включая путь бот → ядро,
подпись, чужого отправителя, потерю подтверждения отправки и частичный ответ.
