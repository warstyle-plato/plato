# Удаление неиспользуемого уязвимого pycel

На main `40285da4` проверка точных зависимостей обнаружила pycel 1.0b30
только в `requirements-dev.txt`: CVE-2024-53924 / GHSA-pw67-xjhq-389w,
уровень high. По [публичному advisory](https://github.com/advisories/GHSA-pw67-xjhq-389w)
исправленной версии нет; обработка формулы недоверенной книги может выполнить
Python-код. Приватный Dependabot alert #1 через имеющуюся интеграцию не читается
(403), поэтому его состояние не подменяется результатом публичного аудита.

Пакет больше не нужен: гостиничные и нежилые книги уже рассчитываются
собственным `xlsx_eval`, импортов pycel в Python-коде нет. Удалены его требование
и оставшиеся только из-за него зависимости. Production lock не изменён.

Тестовый lock теперь ограничен production lock: networkx совпадает с продом
(3.6.1), прежнее исключение 2.6.3 больше не требуется. Других обновлений версий
нет. Проверка совпадения версий усилена до полного равенства общих пакетов.

Проверка pip-audit 2.10.1 после удаления: 53 production и 58 development
пакетов, известных уязвимостей нет. Проверена установка с обязательными хэшами
без установки приложения. Прямые Windows-зависимости также проверены отдельно;
это не аудит всего транзитивного Windows-окружения.

Проверка книг выполняется с принудительно недоступным импортом pycel и
networkx 3.6.1. Она включает реальные расчёты гостиничной и нежилой книги,
порчу формулы и отказ собственного вычислителя от Python-подобной EVAL-формулы.
Результаты привязаны к точному коммиту в отдельном отчёте исполнителя; окончательное
закрытие требует независимой приёмки и штатных проверок этого SHA.
