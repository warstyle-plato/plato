# Тестовая страница «ГПР — новый вид»

Решение владельца 17.11.2026 («А»): новый вид блока ГПР сначала делается
отдельной тестовой страницей рядом с текущим Монитором. Текущий блок ГПР в
`/monitor` не меняется, пока владелец не сравнит оба вида. После приёмки новый
вид заменяет старый блок, а тестовая страница удаляется.

## Где и как открыть

- Адрес: `/gpr-preview`. Можно указать проект и дату среза в hash:
  `/gpr-preview#project=…&cut=ГГГГ-ММ-ДД`.
- Оболочка страницы открыта, как `/monitor`; данные приходят только с
  `/monitor/gpr-brief` по ключу администратора (`_require_team_access`,
  «Монитор проекта», чтение). Ключ страница берёт тот же, что Монитор
  (`localStorage`); без ключа она просит сначала войти в Монитор.
- Список проектов — `/monitor/report/projects`, как у сводки руководству.

Страница не лежит под `/monitor/`: все маршруты там обязаны проверять доступ
(`tests/test_demo_scope.py`), а это пустая оболочка.

## Один источник

`developaid_gpr_brief.build` раскладывает результат
`developaid_monitor_pace.schedule_view` — того же расчёта, что
`/monitor/gpr-view`. Своих расчётов готовности, состава разделов и прогноза
модуль не делает:

- раздел работы — только ячейка матрицы готовности (`work_ids`);
- готовность корпуса и проекта — `schedule.readiness`;
- плановая дата — плитка `dashboard.schedule.qualified_rnv`;
- выполнение работы — её `display_progress` с датой показания.

Единственное правило страницы — «отстаёт на дату среза»: по плану к дате среза
должно быть выполнено на `LAG_PP` (10) процентных пунктов больше, чем последнее
датированное выполнение. Работа без показания — «нет показания», а не ноль и не
отставание.

## Что на странице

1. «Сроки проекта»: план окончания, ожидаемое окончание, готовность проекта
   (или причина, почему её нет), сколько работ отстаёт; дата показаний один раз.
2. «Корпуса»: готовность, выполнено, отстают, без показания, план окончания.
   На телефоне — строка на корпус.
3. «Требует внимания»: до пяти отстающих работ, одинаковые работы разных
   корпусов — одной записью; порядок — по наибольшему отставанию.
4. «Матрица по разделам»: разделы × корпуса; раздел раскрывается списком работ,
   сгруппированных по названию; отметка «Только отстающие»; на телефоне — один
   корпус с переключателем.
5. «Как считали и ограничения» (свёрнуто): правило отставания, причины
   ограничений из расчёта, число работ вне матрицы.
6. Ссылки на текущий Монитор: подробный график, Платон, файлы, «Данные и
   настройки».

Если график не загружен, страница называет причину из расчёта и ведёт в
«Данные и настройки».

## Чего пока нет

Ожидаемая дата окончания — заглушка (`expected_finish.state = "pending"`) до
слияния единой оценки срока ГПР (PR #1190). Седьмую собственную оценку здесь не
заводить: после слияния плитка читает единую оценку.

Проверки: `tests/test_gpr_preview_page.py` (правило отставания, раздел из
матрицы, доступ, отрисованная страница на 390 и 1440 px).
