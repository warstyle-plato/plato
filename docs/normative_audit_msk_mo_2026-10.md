# Ревизия нормативного блока: Москва и Московская область (октябрь 2026)

Дата сверки: 16.10.2026. Ветка `claude/normative-audit-msk-mo`.

Что сделано:

1. Инвентаризация всех нормативов, которые применяют движок (`main_legacy.py`,
   `engine/*.py`, корневые `parking_norms.py`, `mpt_calculator.py`,
   `vri_benefits.py`, `mo_rngp_reference.py`), книга v4 (`engine/xlsx_book_v4*.py`),
   реестр (`data/normatives/registry.json`) и знания Платона (`engine/agent.py`).
2. Сверка с действующими редакциями. Москва — база «Кодекс» (rnk.ru, текст по
   «Вестнику Москвы», строка «Редакция действует с …» прочитана 16.10.2026).
   Область — цепочка поправок к 713/30 в `docs/normative/mo_rngp_chain/`
   (официальные публикации) и отметка «ред. от 01.09.2026» в КонсультантПлюс.
   Поправок позже названных редакций на 16.10.2026 не найдено; отставание
   правовых баз на 2–4 недели исключить нельзя.
3. Расчёт не менялся. Любое изменение числа или формулы — вопросы владельцу
   (раздел 6). Технические правки (подписи, реестр, документы) — раздел 5.

Обозначения типа нормы: **О** — обязательная формула или показатель;
**С** — справочная возможность, допуск («допускается»); **Р** — решение или
данные органа власти. Статусы: совпадает / расходится / устарела редакция /
нет источника / регион перепутан / нет в коде.

`claude/normative-fix-<предмет>`, тест падает на прежнем поведении, эталоны —

1. **Поликлиника, м² на посещение.** Код: 15 (вводное поле, «нормы города нет»).

   Исполнено: ступени — PR #737, страница — PR #741 (маршрут `/tep/derived-by-site`).

   «Пересчитать по ТЭП» — пунктом 2 по средней квартире; у одного проекта два
   пути могут дать разный паркинг. **Решение владельца (18.10.2026): оставить

4. **Кд для округов вне табл. 3 к 1745-ПП** (Дзержинский, Протвино, Пущино,

   руками; запас 0,1 убрать.
5. **`vri_tep_quick` (быстрый расчёт Telegram)** считает ДОО/СОШ по зоне 1
   (44/90) для любого района; для 28 районов зоны 2 норма 63/124.

## 8. Почему бот не сообщил о поправках к 713/30 (774-ПП, 1080-ПП)

Проверено на проде 16.10.2026 (`/api/normatives`, `/api/normatives/watch`,
`/normatives/delivery`): сторож жив, последняя проверка 11:22, 42 карточки,
поиск включён. Четыре причины, по построению:

1. `source_url` карточки `mo-713-30` — публикация самой поправки 1080-ПП на
   pravo.gov.ru. Страница публикации не меняется никогда, и отпечаток новую
   редакцию увидеть не может. Так же устроено большинство карточек.
2. Единственный способ увидеть новую редакцию — платный поиск, один запрос
   «713/30 утратил силу или внесены изменения», 10 результатов. На проде он дал
   Гарант, Главбух, два нерелевантных документа и проект поправки апреля 2025;
   ни 774-ПП, ни 1080-ПП в выдаче нет.
3. Подписка на уведомления сделана 09.09.2026 (0.22.92) — после 774-ПП (02.07) и
   через неделю после 1080-ПП (01.09). 19.09 владелец принёс оба текста сам;
   с тех пор номера учтены и новостью считаться не должны.
4. Доставка идёт с хоста бота только адресатам из `DEVELOPAID_ADMIN_IDS`;
   на 09.09 бэклог фиксирует список открытым.

Решение владельца (16.10.2026): чинить отдельным PR после ревизии
(`claude/normative-fix-watch`): у карточек со ссылкой на публикацию поправки
добавить адрес консолидированного текста, чей отпечаток меняется с редакцией;
второй поисковый запрос «О внесении изменений в постановление … № 713/30» с
сортировкой по дате. Тест на подделке.
