# Облачный исполнитель с сохранением сессий — проект конфигурации

Это отдельный **SDK-host**, не готовая интеграция всех чатов. Сервис ещё не
создан. Blueprint нельзя применять до независимой приёмки точного кода,
проверок, подтверждения workspace и стоимости нового сервиса.

## Что предлагается разместить

- Один новый background worker `plato-session-dispatcher`, без входящего HTTP
  и публичного URL. Бот и ядро PLATO не меняются.
- Python SDK `openai-codex==0.167.0`; native CLI закреплён зависимостью SDK.
  Dockerfile копирует только код исполнителя, без приложения и документов.
- Один постоянный диск 1GB в стандартном `/root/.codex`: сохраняются вход,
  SDK-сессии и приватная очередь. HOME/CODEX_HOME не переопределяются.
- Начальный режим read-only с запретом подтверждений от имени пользователя.
  Задачи ставятся локальным операторским CLI, рабочий процесс читает очередь.
  Никакие произвольные GitHub-комментарии не запускаются автоматически.

По [текущему тарифу Render](https://render.com/pricing) на 07.11.2026
`1c-2g` — $25/месяц, диск — $0.25/GB в месяц: ориентир **$25.25/месяц**
за этот новый worker+диск. Это не включает возможные платежи за workspace,
дополнительные ресурсы и использование модели. Подтверждение облачного
размещения само по себе не означает согласия с этими новыми расходами.

## Безопасный порядок подготовки

1. Проверить единственный выбранный workspace пользователя, отсутствие уже
   созданного такого исполнителя и точный source принятого PR. Не применять
   корневой Blueprint приложения и не включать автоматическое применение.
2. После подтверждения стоимости создать **только** изолированный worker.
   Поле `autoDeployTrigger: off` выключает последующие автодеплои, но не
   отменяет первый запуск при создании сервиса.
3. Проверить build/deploy до `live`; рабочий процесс до постановки задач
   должен ожидать. `live` ещё не доказывает вход или выполнение SDK-задач.
4. На **новом выделенном хосте**, через приватную операторскую консоль,
   выполнить штатный device-code вход. Не брать auth.json из нынешнего
   управляющего разговора и не читать его содержимое:

   ```sh
   python -c 'import os; from codex_cli_bin import bundled_codex_path; p=str(bundled_codex_path()); os.execv(p,[p,"login","--device-auth"])'
   ```

   SDK wheel не создаёт console script `codex`, поэтому используется его
   проверенный native helper. Вход по коду обозначен OpenAI как beta; его
   доступность зависит от настроек аккаунта/workspace. Ссылку открыть на
   телефоне и подтвердить вход штатно. Не публиковать код, auth cache или
   приватный лог входа в GitHub/общие логи/чат. Не выходить из текущего
   приложения на телефоне и не менять его авторизацию ради этого хоста.
5. Выполнить один ограниченный проверочный запрос без клиентских данных.
   Затем второй immutable request в той же задаче: должен продолжиться тот
   же SDK thread. Проверить перезапуск сервиса и сохранность привязки.
6. Проверить допустимость Codex sandbox на реальном Render-хосте. Если
   платформа не поддерживает требуемую изоляцию, это блокер: не включать
   обход sandbox и не называть простой ответ модели проверкой исполнения.

`serve` без сети входящих запросов не предоставляет HTTP-health endpoint.
Ожидание/ошибки авторизации и безопасный статус проверяются операторским CLI.
Содержимое prompt/result и thread IDs остаются в приватном store.

У диска нет zero-downtime deploys и нельзя менять shutdown delay. При
неопределённом исходе turn после остановки не выполнять его повторно вслепую:
нужны сохранённый turn ID и проверка результата, иначе `needs_attention`.

## Что ещё нужно для полной связи с отдельными чатами

Первый metadata transport готовится отдельно в PR1038. Этот host-компонент
не превращает публичный отчёт или заявленную роль в право запустить работу.
Нужен отдельно принятый управляющий канал постановки **приватных** задач и
возврата результатов. До его проверки операторский CLI — единственная
точка ввода; автоматического запуска из чужой переписки нет.

SDK threads на собственном сервере не гарантируют появления в списке Codex
Cloud chats мобильного приложения. Это необходимо проверить до выбора
окончательного пользовательского интерфейса. Диск с приватной историей
не публикуется в GitHub и не включается в архивы передачи.

Новый сервис, оплаченный хостинг, готовый вход и тест чужого UI-чата пока
**не выполнены**. Ни этот документ, ни локальные тесты не являются допуском
к изменению прав, секретов, платежей, ядра или существующей очереди выпуска.
