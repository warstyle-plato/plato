# Куда это положить

Самый простой тестовый вариант: GitHub + Render.

## 1. GitHub
Создайте новый пустой репозиторий, например `plato-model`.

Распакуйте этот ZIP и загрузите В КОРЕНЬ репозитория три файла:
- `main.py`
- `requirements.txt`
- `DEPLOY.md`

## 2. Render
Создайте новый Web Service и подключите репозиторий GitHub.

Параметры:
- Language: Python 3
- Build Command: `pip install -r requirements.txt`
- Start Command: `uvicorn main:app --host 0.0.0.0 --port $PORT`

Нажмите Deploy.

После успешной сборки Render даст адрес вида:
`https://plato-model-xxxx.onrender.com`

Откройте его в Safari/Chrome на компьютере или телефоне.

Важно: это тестовый MVP интерфейса и части расчётного ядра.
Финальный кредитный блок БРИДЖ → ПФ → эскроу → проценты → налоги → LLCR ещё не перенесён с полным паритетом Excel.

## Тестовый стенд на Yandex Cloud

Веб без Telegram: токены не нужны, приложение поднимается и без них.

```bash
git clone https://github.com/warstyle-plato/plato.git && cd plato
sh run.sh
```

`run.sh` сам создаёт `.env` из примера, собирает образ, гасит прежний контейнер,
поднимает новый и ждёт, пока `/health` ответит. Плагин Docker Compose для этого
не нужен — на чистой виртуальной машине его обычно нет, и `docker compose up`
завершается сообщением `docker: unknown command: docker compose`, а старый
контейнер продолжает работать со старым кодом.

Обновление после `git pull` — та же команда:

```bash
git pull && sh run.sh
```

Остановить и посмотреть журнал:

```bash
sh run.sh stop
sh run.sh logs
```

Через Compose, если плагин установлен:

```bash
docker compose up -d --build
```

Открывается по `http://<внешний-IP>:8080/`.

### Если страница не открывается

Проверяйте по порядку — первая же команда, которая ответит не тем, укажет причину.

```bash
docker ps                         # контейнер developaid должен быть Up
docker logs --tail=50 developaid  # причина падения
ss -ltnp | grep 8080              # порт должен слушаться на 0.0.0.0
curl -sS localhost:8080/health    # {"status":"ok","version":"..."}
```

**`address already in use` при запуске.** Порт держит контейнер, поднятый
раньше под другим именем — например через `docker compose`, где имя собирается
из имени папки. `run.sh` находит такие контейнеры по порту и гасит сам; если
порт занял обычный процесс на хосте, скрипт покажет его и остановится.

```bash
docker ps                         # посмотреть, что занимает порт
sudo ss -ltnp | grep 8080
```

**Версия в `/health` не совпадает с `git log`.** Значит работает старый
контейнер: сборка не выполнялась. Чаще всего `docker compose` отсутствует и
команда завершалась ошибкой, которую легко не заметить. Запустите `sh run.sh` —
он пересоберёт образ обычными командами docker.

Частые причины:

- **`Failed to connect to localhost port 8000`** — приложение внутри контейнера слушает 8000,
  а наружу проброшен `APP_PORT` (по умолчанию 8080). Снаружи и с самой ВМ обращайтесь к 8080.
- **Порт слушается на `127.0.0.1`** — в `.env` не задан `APP_BIND=0.0.0.0`.
- **Локально `/health` отвечает, а из браузера нет** — порт закрыт группой безопасности
  Yandex Cloud. Разрешите входящий TCP на `APP_PORT` для вашего адреса.
- **Контейнер сразу Exited** — почти всегда нет файла `.env`; `env_file` требует его наличия.

### Что проверить на стенде

- `GET /land/providers` — видны ли геокодеры, не отключилась ли проверка сертификата НСПД;
- поиск участка по кадастровому номеру, по адресу и по координатам;
- кадастровый номер `50:*` Новой Москвы должен уйти в расчёт по ГлавАПУ, а не в областной;
- выгрузка модели: `00_Модель_….xlsx` открывается в Excel и пересчитывается.
