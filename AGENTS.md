# PLATO / DevelopAid — вход для Codex

Владелец закрыл прежние Claude-сессии. Текущий разговор с владельцем — контроль
работы, продолжателей и очереди выпуска. Другая контрольная сессия не требуется.

## Начало работы

1. Прочитай [архитектуру сессий](docs/work_sessions/README.md),
   [реестр](docs/work_sessions/registry.json) и карточку своей задачи.
2. Общие технические инварианты находятся в [CLAUDE.md](CLAUDE.md).
   Это сохранённое имя файла правил, а не действующий маршрут к прежним сессиям.
3. Проверь живой PR, HEAD, состав изменений и относящиеся к нему проверки.
   Реестр — датированный снимок; он не заменяет GitHub и проверку среды.
4. Для независимой работы используй отдельную ветку и worktree. Не меняй
   рабочие копии соседних ролей и не публикуй частные контексты восстановления.

## Полномочия

- Контроль назначает исполнителя, проверки и независимых стражей, собирает
  результат и сообщает владельцу состояние. Авторитет — текущие указания владельца.
- Подагенты выполняют конкретные поручения; сами не сливают PR, не выпускают
  приложение и не пишут людям во внешние чаты. Публикация кода — в пределах
  выданной задачи и оговорённых границ.
- Слияние и прод выполняет контроль по актуальному поручению владельца после
  необходимых проверок. Не требуй повторного разрешения, если оно уже дано;
  не требуй специальной фразы. При отсутствии разрешения обращайся только
  к владельцу в текущем разговоре, назвав конкретный PR и действие.
- Закрытие старых сессий не отменяет найденные ошибки, финансовую приёмку
  или проверки. Архивная фраза о разрешении не даёт нового права на выпуск.
- Рецензент не одобряет собственный патч. Результат проверки привязан к HEAD,
  области и доказательствам; после правок затронутые проверки актуализируются.

## Продолжение после перерыва

Передай новой рабочей сессии её файл из `docs/work_sessions/roles/` и карточку
из `docs/work_sessions/tasks/`. Она восстанавливает контекст по файлам и коду,
а не притворяется прежней сессией. Для нового контрольного разговора используй
[передачу контроля](docs/work_sessions/CONTROL_HANDOFF.md).

Роли запускаются по задаче. Запись роли в реестре не означает постоянно
работающий процесс или отдельный постоянный чат в интерфейсе.
